🔑 Core Ideas
Overcommit & Demand Paging

Linux lets processes map (reserve) more memory than the physical RAM installed.

Example: 16 GB RAM system may have 50 GB of memory mapped by processes.

Why possible? Because not all mapped memory is used at once, and only the actually accessed pages get allocated ("demand paging").

Memory Reclaim

When RAM fills up, Linux must reclaim memory to make room for new allocations.

Two types of reclaim:

Page cache reclaim (file-backed pages):

If a page is clean (unchanged), kernel can drop it → free instantly.

Downside: if accessed again → major page fault (reload from file).

Anonymous memory reclaim (non-file pages like heap, stack):

Cannot just drop → must swap out to disk.

Swap & Its Purpose

Swap ≠ extra memory or backup reserve.

Real purpose: allow reclaim of anonymous memory (so it doesn’t all have to stay in RAM).

Without swap: only page cache can be reclaimed → risk of thrashing.

With swap: kernel can balance reclaim between page cache and anonymous memory.

Thrashing

Happens under heavy memory pressure: system constantly swaps in/out or reloads file pages → CPU always waiting on I/O.

System becomes unusable (slow, unstable).

Swap helps mitigate by spreading pressure across both caches.

Swap Cache

Think of it as a buffer/bridge for anonymous memory.

When a page is swapped out:

It first enters the swap cache (kernel’s temporary repository).

Swap cache tracks whether the page is:

Already written out to disk,

About to be written,

Or just swapped back in.

Purpose: avoids race conditions if multiple processes try to access/swap the same page concurrently.

Analogy: page cache handles file-backed pages, swap cache handles anonymous pages.

Swapper Spaces (Implementation Detail)

Kernel organizes swap cache using a structure:

swapper_spaces:

2D array → outer dimension = max number of swap files (MAX_SWAPFILES).

Each entry points to an array of struct address_space.

Each struct address_space:

A "fake" page cache object for swap.

Describes up to SWAP_ADDRESS_SPACE_PAGES pages = 16,384 pages (≈64 MiB with 4 KiB pages).

Finding a Page in Swap

To locate a page in swap cache:

You need:

Swap file index (aka “type”) → which swap device/file.

Page offset inside it.

Combine both → swap entry (swp_entry_t).

Internally: swp_entry_t just wraps an unsigned long, architecture-independent.

📌 Key Takeaways
Overcommit & demand paging: Linux promises more memory than RAM, allocating only on access.

Page cache reclaim = drop clean file-backed pages; Anonymous reclaim = must swap.

Swap’s true purpose = reclaim anonymous memory, not extend RAM.

Swap cache = staging area to coordinate swap-out/in for anonymous pages.

Swapper spaces + swap entries = kernel’s data structure to locate swapped pages efficiently.

Thrashing risk = swap + reclaim balance helps mitigate it.

👉 So the big picture:

Linux balances memory between file-backed (page cache) and anonymous memory using reclaim + swap.

Swap cache + swap entries provide the kernel machinery to track and safely manage anonymous memory being moved between RAM and disk.

When the kernel reclaims anonymous memory, it must swap it out. This involves:

Putting pages into the swap cache.

Updating page tables (PTEs) to point to swap entries.

1. Swapper Spaces & Swap Entries
swapper_spaces[MAX_SWAPFILES]

2D array → one entry per swap file/partition (“type”).

Each entry points to an array of struct address_space (fake page cache objects).

Each address_space covers SWAP_ADDRESS_SPACE_PAGES (16,384 pages = 64 MiB).

swp_entry_t (Listing 12-2)

Architecture-independent encoding of a swap location.

Wraps an unsigned long holding:

Type = which swap file.

Offset = which page inside that file.

Helper functions:

swp_entry(type, offset) → create a swap entry.

swp_type(entry) → extract swap file index.

swp_offset(entry) → extract page offset.

swap_address_space(entry) → get address_space for a given swap entry.

2. Swap Entry in PTEs
When a page is swapped out, its PTE no longer points to physical RAM. Instead:

is_swap_pte(pte) → checks if a PTE contains a swap entry (not present in RAM, but not “none” either).

swap_entry_to_pte(entry) → encodes a swp_entry_t into a PTE (arch-specific).

pte_to_swp_entry(pte) → extracts back the swp_entry_t.

Clears flags (pte_swp_clear_flags) but preserves swap-related metadata.

On x86-64, high bits of the offset are inverted (L1TF mitigation).

👉 This lets the page fault handler later swap the page back in.

Triggered via swapon().

Calls init_swap_address_space(type, nr_pages):

Allocates enough struct address_space objects (via kvcalloc).

Initializes them (no writeback tags).

Stores them in swapper_spaces[type].

So, every swap file is prepped with fake address spaces to represent ranges of pages.

Why needed?

To track which swap entry a folio (page) is associated with.

Prevents races when reclaim, page faults, and writeback collide.

Process:

PG_swapcache flag on folio.

folio->private = swp_entry_t (maps folio → swap entry).

folio_mapping() returns either:

Normal file mapping (folio->mapping).

Or swap cache mapping if PG_swapcache is set.

👉 This is how anonymous memory behaves as if it had a file backing in swap.

1. pageout() (Listing 12-26)
Called by shrink_page_list() when a folio is dirty and must be written.

Steps:

Call folio_clear_dirty_for_io()

Clears dirty flag, marks folio read-only in all mappings.

Ensures any further writes generate a fault (so we can track).

Set PG_reclaim flag (marks folio under reclaim).

Invoke mapping->a_ops->writepage() → in swapper’s case, this is swap_writepage().

Use batched writes (SWAP_CLUSTER_MAX = 32) for efficiency.

👉 Result: Asynchronous I/O is queued to write the folio’s contents into the swap device.

2. swap_writepage() (Listing 12-27)
Called via ->writepage for swapper mappings.

Logic:

First, try try_to_free_swap(page) → if swap slot is no longer needed, skip write.

Else, call __swap_writepage().

Handles stale entries (no need to waste I/O if nothing references swap slot).

3. __swap_writepage() (Listing 12-28)
Actually builds and submits the I/O request.

Steps:

Get swap entry metadata (page_swap_info(page)).

If filesystem-backed swap → delegate to swap_writepage_fs().

Else for block device:

Allocate struct bio.

Fill with:

REQ_OP_WRITE | REQ_SWAP flags.

Sector = swap_page_sector(page).

Attach page → bio_add_page().

Mark page PG_writeback.

Unlock page (others can now wait on it).

Submit via submit_bio(bio).

Completion handler: end_swap_bio_write().

Calls end_page_writeback() → clears PG_writeback, requeues page if needed.

👉 At this point, the page’s contents are on disk, pending async completion.

If in swap cache:

Call __delete_from_swap_cache(folio, swap, shadow)

Unlock xarray.

Call put_swap_page() → decrement swap slot reference.

👉 This safely unlinks folio from swap metadata before freeing.

5. __delete_from_swap_cache() (Listing 12-30)
Low-level function to remove folio from swapper’s address_space.

Steps:

Store shadow value (NULL in our case).

👉 Folio is no longer tracked in swap cache, but not freed yet.

Used when swap space is tight or slot is not actually needed.

Conditions checked:

Folio must be in swap cache.

Not under writeback.

Must already have been swapped once (folio_swapped()).

If OK:

Calls delete_from_swap_cache(folio).

Marks folio dirty (since contents weren’t written).

👉 Lets kernel recycle swap slots without unnecessary I/O.

Higher-level wrapper to call __delete_from_swap_cache().

After deletion:

Calls put_swap_page() (drops reference on swap entry).

Calls folio_ref_sub() (decrements folio refcount).

1. Trigger Point
A page fault happens on a swapped-out page.

The PTE (Page Table Entry) is non-empty but marked non-present → kernel knows the page is in swap.

do_swap_page() is called to bring it back.

2. Initial Setup (do_swap_page)
Convert PTE to swp_entry_t → describes which swap device + offset holds the page.

Get metadata via get_swap_device(entry) (ensures swapoff won’t interfere).

Try lookup_swap_cache(entry):

If page already in swap cache → reuse it (no disk read needed).

If not in swap cache → must allocate a page + read from swap.

3. Reading From Disk (Major Fault)
If not cached:

Allocate a fresh page (alloc_page_vma).

Mark it as swap-backed (__SetPageSwapBacked).

Add to LRU (lru_cache_add).

Call swap_readpage() or swapin_readahead():

Reads from swap device.

May prefetch extra pages (readahead) anticipating future faults.

This is a major fault (I/O involved).

4. Synchronization / Locking
Once page is read, kernel tries lock_page_or_retry():

If page already locked by I/O → retry later.

If lock succeeds → continue.

Ensures only one fault handler installs the page.

5. Edge Case Handling
Several checks ensure correctness:

swapcache validity: Verify page wasn’t freed or swapped again underneath us (PageSwapCache + page_private() vs entry).

Write faults: Must know if mapping is exclusive (nobody else can write):

Use pte_swp_exclusive() or page_count() checks.

If exclusive → map writable directly.

If not exclusive but write fault → fallback to Copy-on-Write (do_wp_page).

Stable writes: If swap backend doesn’t support write-while-writeback (SWP_STABLE_WRITES), drop exclusivity if page still under writeback.

Races: Check if someone else already faulted in the page (pte_same).

SIGBUS handling: If page read failed → mark VM_FAULT_SIGBUS.

6. Installing the Page
Free the swap entry (swap_free(entry)).

Possibly free swap cache (try_to_free_swap(page)) if it’s no longer needed.

Update memory accounting (inc_mm_counter_fast(MM_ANONPAGES), dec_mm_counter_fast(MM_SWAPENTS)).

Create a new PTE (mk_pte(page, prot)), maybe writable (maybe_mkwrite()).

Add page to reverse mapping (page_add_anon_rmap).

Mark soft-dirty if needed (pte_mksoft_dirty).

Finally: set_pte_at() → installs the PTE into the page table.

7. Cleanup & Return
Unlock the page.

Drop swapcache reference if page is different.

Release swap device reference.

Return vm_fault_t code (e.g. VM_FAULT_MAJOR, VM_FAULT_RETRY, VM_FAULT_SIGBUS, etc.).

8. Why So Many Checks?
Concurrency: Other threads may be faulting the same page.

Correctness: Don’t double-map or overwrite data.

Performance: Prefer cache hits, minimize disk reads, support readahead.

Robustness: Handle swapoff, writeback races, SIGBUS conditions gracefully.

✅ In short:
do_swap_page() carefully reconstructs the page from swap → from swap cache if possible, else from disk → validates exclusivity and races → installs a new PTE → frees the swap entry → returns.
