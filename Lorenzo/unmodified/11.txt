🔑 Core Idea
Linux allows overcommit + demand paging + aggressive caching.

This makes the system efficient, but also means memory pressure can arise at any time.

To relieve memory pressure, the kernel uses reclaim, which decides which pages can be freed and reused.

🧩 Two Types of Reclaim
Indirect Reclaim (Proactive)

Trigger: A zone’s free memory drops below low watermark.

Kernel starts background reclaim work (kswapd).

Goal: Bring free memory back to high watermark.

Non-blocking for most processes (unless pressure worsens).

Direct Reclaim (Reactive)

Trigger: A zone’s free memory drops below min watermark.

The allocating process itself is forced to reclaim memory (blocking).

If reclaim fails → OOM killer may be invoked.

🏞️ Watermarks in Zones
Every zone (DMA, Normal, HighMem, etc.) has three thresholds:

High → plenty of free memory.

Low → start indirect reclaim (kswapd wakes).

Min → start direct reclaim (process blocked).

👉 Figure 11-1 shows:

Above WMARK_LOW: allocate directly (fast path).

Between Low & Min: indirect reclaim in background.

Below Min: direct reclaim, process blocks, OOM possible.

⚡ Allocation Paths
Fast Path (__alloc_pages)

Tries to allocate quickly from:

Per-CPU Pages (PCP)

Zones with free pages ≥ WMARK_LOW

If successful → done.

If not → slow path.

Slow Path (__alloc_pages_slowpath)

Invoked when all eligible zones < WMARK_LOW.

May trigger indirect or direct reclaim depending on situation.

Calls reclaim mechanisms, possibly OOM killer.

🔄 Reclaim Mechanism Internals
LRU Lists (Least Recently Used)
Kernel maintains per-zone LRU lists:

Active file (hot page cache)

Inactive file (cold page cache)

Active anon (hot anonymous pages, e.g., heap/stack)

Inactive anon (cold anonymous pages, candidates for swap)

👉 Reclaim logic scans these lists to free:

Page cache → drop clean pages.

Anonymous pages → swap out if needed.

📦 Folio Batches
Instead of handling pages one by one, kernel groups them into folios (larger units, usually multiple contiguous pages).

Folio batches are processed together for efficiency.

⚖️ Overall Flow
Process requests memory → __alloc_pages.

If zone ≥ WMARK_LOW → success (fast path).

If not → slow path → check watermarks.

If between Low & Min → background reclaim (kswapd).

If below Min → direct reclaim → process blocks.

If reclaim fails → OOM killer.

✅ Summary in one line:
Linux keeps memory efficient with caching + overcommit, but uses zone watermarks + reclaim (indirect via kswapd, direct via process) to ensure forward progress, falling back to OOM if memory cannot be freed.

(Listing 11-8)

If reclaim truly failed, trigger OOM killer.

Select a victim process → kill it → free its memory.

Special handling:

If the current thread is already an OOM victim, don’t loop.

Otherwise → fail allocation.

❌ No-Fail Allocations (__GFP_NOFAIL)
(Listing 11-9)

If _GFP_NOFAIL is set:

The allocation must not fail (caller promises it can block forever).

Kernel retries endlessly until success.

May use emergency reserves via ALLOC_HARDER.

👉 Dangerous flag: can stall the system under extreme pressure.

📚 LRU Vectors (Section 1.2, Fig 11-5 → 11-6)
LRU = Least Recently Used policy for deciding which pages to reclaim.

Goal: Evict least recently used memory pages.

Problem: Tracking every access precisely would be too expensive.

Solution: Kernel uses sampling (via _PAGE_ACCESSED / “young bit”) to approximate.

Separate LRU Lists
Instead of one big LRU, kernel maintains 4 lists per zone:

Active file (hot page cache)

Inactive file (cold page cache, reclaimable)

Active anon (hot anonymous pages: heap/stack)

Inactive anon (cold anonymous pages: swap candidates)

👉 4 lists allow precise reclaim: drop cold cache pages first, swap out cold anon pages only when necessary.

Promotion/Demotion
If a page in inactive is accessed → promoted to active.

If an active page is not accessed for a while → demoted to inactive.

Reclaim mostly scans inactive lists.

🔍 folio_check_references() (Listing 11-10)
When reclaim considers a folio:

Count how many PTEs mapping it are marked young (via folio_referenced() → clears the bit).

Check and clear PG_referenced flag.

Decision:

If recently accessed → activate (move to active list).

If borderline (1 reference) → keep in inactive list for another round.

If no references → reclaim (free/swap out).

🔑 kswapd() — the background reclaim daemon
Runs as a kernel thread (started from init process).

Purpose: keep some free memory available even if no active allocations are reclaiming.

Prevents the system from stalling when sudden allocations come in.

Flags:

PF_MEMALLOC → allows access to reserves (won’t block itself).

PF_KSWAPD → marks the thread as the reclaim daemon.

Initializes:

pgdat->kswapd_order = 0 (no reclaim requested yet).

pgdat->kswapd_highest_zoneidx = MAX_NR_ZONES.

pgdat->nr_writeback_throttled = 0.

Then enters an infinite loop:

Reads requested allocation order.

Decides which highest zone index to reclaim (kswapd_highest_zoneidx()).

Calls kswapd_try_to_sleep() (sleep until work).

Performs reclaim with balance_pgdat().

If high-order reclaim fails, drops to smaller orders, but wakes kcompactd for original order.

🔑 kswapd_highest_zoneidx()
Returns the highest eligible zone index that kswapd should reclaim from.

If set to MAX_NR_ZONES, it means:

Either kswapd is running the first time,

Or last reclaim cycle failed to sleep (node still unbalanced).

Falls back to previous zone index if not valid.

🔑 kswapd_try_to_sleep()
Central sleep logic for kswapd.

Steps:

Create a wait entry (DEFINE_WAIT).

If freezing or thread is stopping → exit.

Add to wait queue (prepare_to_wait).

If prepare_kswapd_sleep() says nothing to do → try a short sleep.

Also reset compaction isolation state.

Wake up kcompactd (compaction thread) if fragmentation blocks higher-order allocs.

Sleep for ~0.1s (schedule_timeout(HZ/10)).

If woken too early → reset reclaim order/zone index and retry.

If still quiet → go into long sleep (schedule()) until explicitly woken by alloc slowpath.

While asleep, per-CPU thresholds (NR_FREE_PAGES) are reduced to avoid missing low memory pressure events.

🔑 prepare_kswapd_sleep()
Decides if kswapd can sleep safely.

Checks:

No direct reclaimers throttled (via pfmemalloc_wait).

Node hasn’t exceeded MAX_RECLAIM_RETRIES (16 failed attempts).

If node is balanced (pgdat_balanced()) → means at least one zone has free pages ≥ high watermark.

If node is not balanced → indirect reclaim should continue.

🔑 pgdat_balanced()
Scans zones bottom-up (DMA → Normal → Highmem).

[Memory Pressure / Allocation Request]
   |
   +-- Fast Path (__alloc_pages, WMARK_LOW ok)
   |      -> Immediate allocation, no reclaim
   |
   +-- Slow Path (__alloc_pages_slowpath, below low watermark)
          |
          v
   [Reclaim Starts: shrink_node()]
          |
          v
   [shrink_page_list(folios)]
          |
          +-- Folio Dirty?
          |     +-- Yes:
          |     |     - If kswapd: pageout() -> async writeback
          |     |     - If direct reclaim: skip/rotate
          |     |
          |     +-- No: continue
          |
          +-- Folio Referenced? (pte_young/accessed)
          |     +-- Yes: folio_activate() -> Active LRU
          |     +-- No: continue
          |
          +-- Anonymous Folio?
          |     +-- Yes:
          |     |     - If swap available: add to swapcache, unmap, reclaim
          |     |     - If no swap: rotate back
          |     |
          |     +-- No (File-backed):
          |            - If clean: free immediately
          |            - If dirty: pageout() -> async writeback
          |
          +-- Lazyfree Folio? (madvise(MADV_FREE))
          |     -> mark_page_lazyfree() -> Inactive File LRU, reclaim w/o swap
          |
          +-- Mapping Removal (__remove_mapping)
          |     - Drop from pagecache/swapcache
          |     - Only if clean, unmapped, unpinned
          |
          v
   [Final Outcome per Folio]
      - Free → memory returned
      - Activate → Active LRU
      - Deactivate → Inactive LRU
      - Rotate → Inactive tail
      - Writeback → reclaimed later

[Supporting Mechanisms]
-------------------------------------------------

[LRU Maintenance]
   - folio_add_lru() → new anon/file folios enter inactive
   - folio_activate() → referenced folios promoted
   - deactivate_page()/deactivate_file_folio() → cold folios demoted
   - folio_rotate_reclaimable() → after writeback, rotated tail inactive
   - Unevictable: mlock() → unevictable LRU

[Batching (Per-CPU folio_batch)]
   - Collects ops: add / rotate / deactivate / lazyfree / activate
   - Flushed via:
       - lru_add_drain_cpu (per CPU)
       - lru_add_drain (current CPU)
       - lru_add_and_bh_lrus_drain (also buffer-head LRUs)
       - lru_add_drain_cpu_zone (also PCP freelists, compaction)

[Reclaim Throttling]
   - consider_reclaim_throttle() → check progress
   - reclaim_throttle(reason) → sleep by reason
   - skip_throttle_noprogress() → avoid useless stall
   - throttle_direct_reclaim() / allow_direct_reclaim() → protect reserves

[Lazyfree Path]
   - madvise(MADV_FREE) → mark_page_lazyfree()
   - lru_lazyfree_fn() → inactive file LRU, reclaimable without swap

[mlock/munlock Path]
   - mlock_folio/mlock_new_page → __mlock_page/__mlock_new_page
   - munlock_page → __munlock_page
   - Folios moved to/from unevictable LRU

[Global Disable/Enable Batching]
   - lru_cache_disable() → inc disable_count, drain all CPUs (__lru_add_drain_all)
   - cpu_needs_drain() → check CPU pending batches
   - lru_cache_enable() → dec disable_count, re-enable batching
