🔹 Measuring Free Memory
The free utility shows system memory: total, used, free, shared, cache, swap.

Data comes from /proc/meminfo.

Key fields:

MemTotal → total usable physical memory.

MemFree → pages not used for anything.

Buffers/Cached/SReclaimable → kernel caches (file cache, slab that can be reclaimed).

MemAvailable → estimated memory available for new allocations without swapping or OOM (heuristic, not exact).

🔹 MemAvailable (kernel calculation)
Calculated inside kernel (si_mem_available() in mm/page_alloc.c).

Steps:

Start with free pages minus totalreserve_pages (reserved for emergency).

Add half of page cache size (LRU active+inactive lists), minus zone low watermarks.

Add half of reclaimable slab memory, minus zone low watermarks.

Ignore shmem (since tmpfs/shared memory must be swapped, not dropped).

Result = free + reclaimable (safe to drop) memory.

So → MemAvailable ≈ memory you can safely use without risk of thrashing or OOM.

🔹 Higher Order Folios
Memory isn’t only allocated in 4K base pages (order-0).

Buddy allocator manages folios of order N (2^N pages).

Example: order-5 → 32 × 4K = 128 KiB.

If larger folios are needed but unavailable, smaller ones are split repeatedly.

Problem: fragmentation → enough free memory may exist, but not contiguous.

If allocation fails → might trigger OOM killer.

NUMA systems add complexity: memory may be free but only on other nodes.

To check: /proc/buddyinfo shows per-zone free folios by order.

🔹 Measuring Memory Usage of a Process
Two main interfaces:

/proc/$pid/status
Shows summary fields:

VmRSS → current resident memory in RAM.

VmHWM → peak resident set size (high-water mark).

RssAnon → anonymous mappings (heap, stack).

RssFile → file-backed mappings.

RssShmem → shared memory.

/proc/$pid/smaps_rollup
Walks VMAs, calculates totals:

Pss (Proportional Set Size) → RSS divided by number of processes mapping the page (fixes RSS overcount).

Private/Shared Clean/Dirty → breakdown of memory usage.

AnonHugePages, FilePmdMapped, etc. → advanced breakdown.

More precise than /status.

⚠️ Note: counters are approximate (RSS can lag up to 64 pages). Zero-copy TCP (via vm_insert_pages()) has edge cases.

🔹 Memory Mapping using mmap()
Direct syscall for mapping memory in a process.

Typical signatures:

void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t off);
Params:

addr → preferred address (or NULL).

length → size, auto page-aligned.

prot → protection (READ, WRITE, EXEC).

flags → mapping type (MAP_PRIVATE, MAP_SHARED, MAP_ANON, etc.).

fd/off → file descriptor + offset (if file mapping, else -1).

Returns: pointer to region or MAP_FAILED.

Examples:
Anonymous memory mapping:

File mapping:

Unmap with munmap(ptr, length).

🔹 mmap() Variants

Example:

Maps file into memory so modifications go directly to disk.

Flags:

MAP_SHARED → changes visible to other processes & written to file.

MAP_SHARED_VALIDATE → like MAP_SHARED, but rejects invalid flag combos.

msync() ensures changes are written immediately.

Writes beyond end of file inside same page → ignored.

Writing beyond file size → causes SIGBUS.

2. Private File Mapping (MAP_PRIVATE)
Example:

ptr = mmap(NULL, st.st_size, PROT_READ|PROT_WRITE, MAP_PRIVATE, fd, 0);
Uses Copy-on-Write (COW):

When you write → page is copied into anonymous memory.

Changes are not written to file.

Side-effect:

If file is truncated while mapped, buffer reverts to truncated file (data lost).

If another process modifies the file, your buffer resets to file contents.

3. Fixed Mappings (MAP_FIXED)
Lets you map memory at a specific virtual address.

Example usage: custom allocators, special virtual ranges.

Flags:

MAP_FIXED → overwrite any existing mapping at that range.

MAP_FIXED_NOREPLACE → fail instead of overwriting if range in use.

Trick:

First map a large range with PROT_NONE (not accessible).

Then place smaller fixed mappings inside that reserved space.

Example in book: map 4 TiB with PROT_NONE, then sub-map 100 × 1 MiB ranges.

When kernel cannot allocate memory, OOM Killer runs.
It selects processes to kill to free memory and logs details in dmesg.

unevictable → Pages locked in memory (e.g. via mlock()), cannot be reclaimed.

dirty → File-backed pages modified but not yet written to disk.

writeback → Pages currently being written back (mutually exclusive with dirty).

slab_reclaimable → Kernel slab pages that can be freed by shrinkers (e.g. inode/dentry caches).

slab_unreclaimable → Kernel slab pages that cannot be reclaimed (permanent kernel data).

mapped → File-backed pages mapped into process address spaces.

pagetable → Pages used for process page tables.

bounce → Legacy “bounce buffers” for DMA on 32-bit (irrelevant on 64-bit).

kernel_misc_reclaimable → Miscellaneous kernel pages that could be reclaimed (currently unused).

shmem_thp → Shared memory pages backed by Transparent Huge Pages.

shmem_pmdmapped → Shared memory pages mapped at PMD level (huge mappings).

anon_thp → Anonymous THP usage.

writeback_tmp → Pages under temporary writeback (FUSE FS).

kernel_stack → Pages used by kernel stacks for processes.

all_unreclaimable → If reclaim failed several times on this node, it is marked unreclaimable.

🔹 Zone-Specific Statistics (/proc/zoneinfo style)
Each node is divided into zones: DMA, DMA32, Normal. Each zone prints:

free → Free pages.

boost → Extra watermark boost due to fragmentation.

min, low, high → Zone watermarks. Allocation below these triggers reclaim.

reserved_highatomic → Pages reserved for atomic high-order allocations.

active_anon, inactive_anon, active_file, inactive_file → Same as global, but per-zone.

unevictable → Pages locked/unreclaimable in this zone.

writepending → Pages dirty or under writeback.

present → Total physical pages in this zone.

managed → Subset of present that buddy allocator manages (excludes reserved).

mlocked → Pages pinned via mlock().

bounce → Bounce buffers in this zone.

free_cma → Free contiguous pages in CMA area.

🔹 Buddy Allocator Statistics
Shows how many free folios (blocks of contiguous pages) exist at each order (2^n pages).

Example:

Order-0 = 1 page (4 KiB).

Order-1 = 2 pages (8 KiB).

…

Order-10 = 1024 pages (4 MiB).

Important for higher-order allocations (e.g. huge pages, big DMA buffers).

Fragmentation = enough free memory exists overall, but not enough contiguous at higher order.

🔹 Migrate Types
Each buddy block is tagged with a migrate type (preference for usage):

U = UNMOVABLE → Kernel pages, cannot be relocated.

M = MOVABLE → User pages, can be migrated around.

E = RECLAIMABLE → Kernel slab pages, can be shrunk/reclaimed.

H = HIGHATOMIC → Reserved for urgent atomic allocations.

C = CMA → For devices needing contiguous DMA buffers.

I = ISOLATED → Temporarily isolated for migration/compaction.

👉 Rules:

If a migrate type is exhausted, kernel may “steal” from others.

H, C, I types cannot be stolen.

Too many Unmovable pages → fragmentation, prevents higher-order allocs.

Tracking per-order migrate types shows if fragmentation or bad usage is the issue.

At end of OOM report:

swap cache → Pages in swap cache.

Free swap → Available swap pages.

Total swap → Total swap configured.

pages RAM → Total RAM in pages.

HighMem/MovableOnly → Legacy highmem region stats.

reserved → Reserved physical pages (not usable for allocations).

🔹 POSIX Shared Memory
Successor to old System V shared memory.

Uses a file descriptor (like regular files) but in /dev/shm/.

Size set with ftruncate(fd, size).

👉 Implementation: Kernel creates a tmpfs-backed file with no directory entry.

Example flow:

Server calls shm_open("test", O_CREAT|O_RDWR, 0666) → gets fd.

Calls ftruncate(fd, SIZE) → sets memory size.

Calls mmap(fd, PROT_READ|WRITE, MAP_SHARED) → maps.

Writes to ptr[].

Client calls shm_open("test", O_RDWR, 0666) → gets same fd.

mmap → sees same memory.

🔹 Anonymous Shared Memory Across fork
Normally, when parent forks, memory is copy-on-write, so no sharing.
But if parent uses mmap(NULL, size, PROT_READ|WRITE, MAP_SHARED|MAP_ANON, -1, 0) before fork:

Parent and child see the same physical pages.

No file, no name — it’s just shared anonymous RAM.

Demo:

Parent writes at ptr[0].

Child writes at ptr[1].

Both can see each other’s changes.

👉 Behind the scenes: kernel creates an unlinked tmpfs file as backing.

🔹 memfd Shared Memory
Most modern and powerful.

memfd_create("name", MFD_ALLOW_SEALING) → creates an anonymous RAM-backed file.

Lives under /proc/<pid>/fd/<n>.

You can ftruncate() it, mmap() it, and pass the fd to another process.

Unlike POSIX shm, not tied to /dev/shm.

Supports sealing (via fcntl(F_ADD_SEALS, flags)):

F_SEAL_SHRINK → can’t shrink.

F_SEAL_GROW → can’t grow.

F_SEAL_SEAL → no more seals can be added.

Server flow:

memfd_create("test", MFD_ALLOW_SEALING).

ftruncate(fd, SIZE).

Seal size with fcntl(fd, F_ADD_SEALS, F_SEAL_GROW|F_SEAL_SHRINK|F_SEAL_SEAL).

mmap() it.

Print /proc/self/fd/<fd> → symbolic link path to pass to client.

Client flow:

Open fd path passed (e.g. /proc/1234/fd/4).

mmap(fd, …, MAP_SHARED).

Both processes share updates.

👉 memfd is preferred today (used by systemd, Wayland, etc.) because it’s flexible, doesn’t rely on /dev/shm, and supports sealing.

🔹 Caveats for FAANG Core Teams & Apple Arm UK
NUMA-awareness: Be ready to tie zoneinfo, node stats, and zone_reclaim_mode into allocation failures.

Fragmentation: Must explain why OOM or THP failure occurs despite high MemFree (buddy allocator fragmentation, migrate types).

OOM selection: Understand oom_score_adj, cgroups v2 limits, and why container workloads tune them.

Page tables: Apple Arm UK will ask about ARM64 multi-level translation tables, TLB shootdowns, and ASIDs.

Tunables: FAANG infra expects reasoning about swappiness, overcommit, dirty limits in large-scale systems.

Shared memory: Modern choice is memfd with sealing + fd passing. System V shm is legacy. POSIX shm is intermediate.

Security: Apple interviewers emphasize mmap_min_addr, mprotect W^X, PAC/BTI integration.
