which Linux ultimately writes data back to disk from
the page cache. The kernel must maintain a trade-off
between caching writes in memory and writing back
to disk and handle scenarios under which dirtying ex-

📝 Linux Writeback — Complete but Simple Explanation
Writeback = the process of taking dirty data in page cache (RAM) and writing it back to the backing storage (disk, SSD, etc.).

The kernel must balance:

✅ Caching writes in memory (fast)

✅ Writing them back to disk (slow, permanent)

❌ Avoiding memory overload when dirty pages exceed limits

🔑 Key Concepts
Clean vs Dirty Pages

Clean: In sync with disk (uptodate).

Dirty: Modified in memory but not yet written to disk.

Writeback Triggers

Automatic/background (periodic checks or thresholds exceeded).

Explicit/user-requested (sync(), fsync(), etc.).

⚙️ Stages of Writeback
Dirty Tracking

When data is written → both the folio (page in cache) and the inode (file metadata) are marked dirty.

Marking is done via:

address_space->i_pages xarray with PAGECACHE_TAG_DIRTY using xas_set_mark().

This lets kernel scan dirty pages fast (xas_for_each_marked()).

Dirty Page Balancing

Each write checks thresholds:

vm.dirty_bytes / vm.dirty_ratio → if exceeded → block writer until writeback runs.

Background Dirty Page Balancing

If not blocking → check against softer thresholds:

vm.dirty_background_bytes / vm.dirty_background_ratio.

If exceeded → wake up the writeback kernel thread (background worker).

Manual Synchronisation

User/system calls (sync(), fsync(), fdatasync()) force writeback immediately.

Background Writeback Timer

Even if no thresholds exceeded, kernel wakes periodically after vm.dirty_writeback_centisecs to check.

Expire Dirty Data

Dirty pages older than vm.dirty_expire_centisecs must be written out.

Writeback to Block Device

Finally, writeback translates into block I/O operations to the storage device driver.

📦 Data Structures
struct inode
↳ Has struct address_space → represents file’s cached pages.

struct address_space->i_pages
↳ xarray of folios (pages). Dirty pages are tagged here.

struct backing_dev_info (BDI)
↳ Represents a backing device (disk/SSD).
↳ Each BDI has writeback limits tied to its I/O bandwidth.

struct bdi_writeback
↳ Tracks writeback state of a BDI.
↳ Contains lists of dirty inodes (like b_dirty).

inode_to_wb()
↳ Maps inode → appropriate bdi_writeback object.

cgroups (optional)

If CONFIG_CGROUP_WRITEBACK=y → writeback bandwidth can be subdivided per cgroup.

Then each inode carries its i_wb pointer to correct writeback object.

📌 How Dirtying Happens
System call write()
→ Copies data to page cache → marks pages + inode dirty.

Page fault on mmap() file
→ Modifying file-backed pages via memory-mapping also dirties pages.

Threshold tuning questions:
Know difference between dirty_ratio, dirty_background_ratio, dirty_bytes, and timers (dirty_writeback_centisecs, dirty_expire_centisecs).

Scalability:

Why use xarray tags for dirty pages → avoids O(n) scans.

Why track inodes separately → efficient batch writeback.

Cgroups:

Writeback isolation per cgroup ensures fair bandwidth.

Consistency:

Writeback does not guarantee durability unless user triggers fsync() or sync().

Crashes may lose dirty data still in cache.

Trade-off:

Too much caching = latency on flush

Too aggressive writeback = wastes bandwidth

🔑 Big Picture
When data is modified in memory (page cache), the kernel must:

Mark it dirty (so it knows to write it back later).

Track the inode associated with those dirty pages.

Eventually write it back to the disk safely, avoiding corruption (like torn writes).

This whole machinery involves:

folio_mark_dirty() → marks the page dirty

__mark_inode_dirty() → adds inode to dirty list

writeback threads → flush dirty data

folio_wait_stable() → prevents races while flushing

1. Marking the Folio Dirty
📄 Code: __folio_mark_dirty()

Locks the address_space->i_pages xarray.

Calls folio_account_dirtied() to update statistics.

Uses __xa_set_mark(..., PAGECACHE_TAG_DIRTY) to tag the folio as dirty in the xarray.

This lets kernel quickly scan only dirty pages instead of all pages.

Also marks the inode dirty, since file metadata must be updated too.

👉 Dirty tracking = folio (page cache) + inode metadata.

2. Marking the Inode Dirty
📄 Code: __mark_inode_dirty()

Gets the inode’s superblock (inode->i_sb).

Gets the bdi_writeback structure via inode_to_wb().

Uses spinlocks (i_lock, wb->list_lock) to update inode state safely.

If inode wasn’t dirty before:

Adds it to bdi_writeback->b_dirty list (queue of inodes needing writeback).

Records timestamp (inode->dirtied_when = jiffies).

Ensures ordering: dirty inodes are written out in time order.

If it’s the first dirty inode for this BDI → wakes up the writeback thread (wb_wakeup_delayed()).

👉 This step ensures kernel knows which files need flushing.

📄 Code: Listing 10-7.

Used for filesystems/devices requiring stable page writes (NFS, some block devices).

👉 Prevents torn writes:

Example: Buffer = AAAAAA.

Kernel flushes first 3 bytes → disk has AAA.

User writes new BBBBBB to buffer before flush completes.

Final flush gives AAABBB → corruption.

With folio_wait_stable() → kernel waits until flush finishes before new writes.

🔑 The Problem
Dirty pages (modified in RAM) must eventually be written to disk.
Userspace can request this explicitly via:

sync() → sync everything (all filesystems).

syncfs(fd) → sync only the filesystem containing fd.

fsync(fd) → sync one file fully (data + metadata).

fdatasync(fd) → sync only essential data + metadata (skip access/mod time updates).

All of these sit on top of the same writeback machinery, which tracks dirty folios and dirty inodes.

1. generic_write_sync()
📄 Listing 10-14

Called after a write if file was opened with O_SYNC/O_DSYNC or if application explicitly requests sync.

Checks if the I/O control block (kiocb) is synchronous (iop_is_dsync).

If yes → calls vfs_fsync_range() to flush the just-written range.

Otherwise just returns.

👉 Ensures synchronous writes flush data to disk immediately.

2. sync() System Call
📄 Listing 10-15

SYSCALL_DEFINE0(sync)
{
    ksys_sync();
    return 0;
}
This is the system call implementation — just calls ksys_sync().

Equivalent to running sync command in shell.

3. ksys_sync()
📄 Listing 10-16

Steps:

Wake up flusher threads

wakeup_flusher_threads(WB_REASON_SYNC) → submit pending dirty folios for writeback in parallel across devices.

Synchronously writeback inodes + metadata

iterate_supers(sync_inodes_one_sb, NULL) → flush all inodes for all mounted superblocks.

iterate_supers(sync_fs_one_sb, &nowait) → flush FS metadata asynchronously.

iterate_supers(sync_fs_one_sb, &wait) → flush FS metadata synchronously.

Sync block devices

sync_bdevs(false) → async flush of blockdev pages.

sync_bdevs(true) → wait for them to finish.

👉 So ksys_sync() submits all dirty data + metadata + blockdev buffers, then waits until complete.

sb->s_op->sync_fs(sb, 0) → async sync of FS metadata.

sync_blockdev_nowait(sb->s_bdev) → async flush of blockdev buffers.

sync_inodes_sb(sb) → wait for inode folio writeback.

sb->s_op->sync_fs(sb, 1) → wait for metadata writeback.

sync_blockdev(sb->s_bdev) → wait for blockdev sync.

👉 Same as sync(), but restricted to one filesystem.

5. fsync() and fdatasync()

6. vfs_fsync_range()
📄 Listing 10-19

Dispatches the sync to the filesystem implementation:

Calls file->f_op->fsync(file, start, end, datasync).

If FS doesn’t implement fsync → returns -EINVAL.

👉 Most filesystems use generic_file_fsync().

7. generic_file_fsync()
📄 Listing 10-20

Steps:

Calls __generic_file_fsync().

After data+metadata sync, issues a block device flush with blkdev_issue_flush() to push hardware write caches to disk (important for durability).

8. __generic_file_fsync()
📄 Listing 10-21

👉 Ensures both file data and metadata are flushed in correct order.
