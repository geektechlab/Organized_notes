# 🔹 **1. Kernel vs User-space Memory Layout**
 
Every process on Linux has its own **virtual address space**, described by its mm_struct.
 
### **User space (per process)**
 Low addresses +-----------------+ | .text/.rodata   |  (code, constants, mapped read-only) +-----------------+ | .data/.bss      |  (globals, uninitialized data) +-----------------+ | Heap (brk/sbrk) |  (malloc(), grows upward) +-----------------+ | mmap region     |  (files, shared libs, anon mappings) +-----------------+ | Thread stacks   |  (each thread has its own, grows downward) +-----------------+ High addresses  
 
- VMAs (vm_area_structs) represent these ranges in an rb-tree + linked list in the mm_struct.
 
- Threads share the same mm_struct → same VMAs.
 

 
### **Kernel space (global, shared by all processes)**
 +-----------------------+ | Kernel .text/.data    | | Modules, vmalloc,     | | vmemmap (struct page) | | Fixmap, per-cpu vars  | | Direct mapping of RAM | +-----------------------+  
 
- Each thread also has a **separate kernel stack** in kernel space.
 

  
# 🔹 **2. VMAs (Virtual Memory Areas)**
 
 
- Per-process structures in mm_struct.
 
- Define contiguous regions of virtual memory with same properties.
 
- Backed by: 
 
  - anonymous pages (heap, stack),
 
  - file mappings (mmap),
 
  - special kernel mappings (e.g., /dev/mem).
 

 
 
- Managed in: 
 
  - **RB-tree** (ordered by address, with subtree max-gap for fast gap search).
 
  - **Interval tree** (for overlap queries, used by reverse mapping).
 

 
 

 
**Operations:**
 
 
- mmap → create/merge new VMA.
 
- munmap → remove/split VMAs.
 
- mprotect, mlock, madvise → may split VMAs.
 
- Merge & split reduce fragmentation, keep trees balanced.
 

  
# 🔹 **3. File Cache vs Page Cache**
 
 
- **Page cache** = kernel-global cache of file data, keyed by (inode, page index). 
 
  - Implemented with **xarray** (mapping->i_pages).
 
  - Holds struct page* objects.
 

 
 
- **File cache** = colloquial name for the same mechanism.
 

 
### On read(fd, buf):
 
 
1. Lookup page in page cache.
 
2. If not present → allocate, load from disk.
 
3. Copy to user buffer.
 

 
### On mmap(file) + page fault:
 
 
1. Lookup page in page cache via inode->address_space.
 
2. Map it into process page tables.
 
3. VMA tells kernel *where* to insert mapping.
 

 
👉 **Key difference:**
 
 
- **read/write** don’t need VMAs.
 
- **mmap** needs VMA to connect file pages to process address space.
 

  
# 🔹 **4. mmap vs brk vs read/write**
 
 
- **brk/sbrk**: grow the heap (contiguous). Used by malloc for small allocs.
 
- **mmap**: create new VMAs (file-backed or anonymous). Used for large allocs or shared mappings.
 
- **read/write**: kernel I/O path via page cache, copies to/from user buffers, no new VMA.
 

  
# 🔹 **5. userfaultd**
 
 
- Special syscall/fd interface.
 
- Lets user-space handle page faults for VMAs.
 
- Normal kernel: demand paging automatically fetches/allocates.
 
- With userfaultd: kernel pauses faulting thread, delivers event to user-space daemon. Daemon fills page (UFFDIO_COPY / UFFDIO_ZEROPAGE).
 

 
### Use cases:
 
 
- Live VM/container migration (pull pages from remote lazily).
 
- Checkpoint/restore (CRIU).
 
- User-space paging (custom DBs, caches).
 
- Debugging (first-touch monitoring).
 

 
### Caveats:
 
 
- Performance hit (fault → kernel → user → kernel).
 
- DoS risk if daemon stalls.
 
- Limited support (mostly anon + shmem).
 
- Security safe: kernel enforces boundaries, but daemon bugs can hang processes.
 

  
# 🔹 **6. mlock & resident pages**
 
 
- mlock()/mlockall() pins pages in RAM (sets VMA flag VM_LOCKED).
 
- Prevents swap/reclaim.
 
- Resident Set Size (RSS) = pages currently in RAM and mapped.
 
- Useful for crypto, real-time apps, but adds memory pressure.
 

  
# 🔹 **7. fd vs VMA vs file**
 
 
- **fd (file descriptor)** = per-process handle → struct file.
 
- **struct file** = kernel object (per-open instance). Refcounted.
 
- **inode + address_space** = underlying file, page cache state (global).
 
- **VMA** = per-process mapping → describes *where in virtual memory* that file or anon region is mapped.
 

 
### Relationships:
 
 
- Closing fd doesn’t remove VMA (VMA holds ref to struct file).
 
- Multiple processes can mmap the same file → each has its own VMAs, but share the same inode->address_space (so same physical cached pages).
 

  
# 🔹 **8. Data structures**
 
 
- **Page cache**: xarray (mapping->i_pages).
 
- **VMAs**: rb-tree (mm->mm_rb), interval trees for overlaps.
 
- **Buddy allocator**: manages free physical pages (power-of-two blocks), not rb-tree.
 
- **LRU lists**: track active/inactive pages for reclaim.
 
- **Writeback queues**: track dirty pages to flush.
 

  
# 🔹 **9. Gap finding for mmap**
 
 
- Kernel finds free virtual address gaps with **augmented rb-tree**: 
 
  - Each VMA node stores rb_subtree_gap (largest hole in subtree).
 
  - Search is O(logN), not linear.
 
  - For top-down mmap: walk right-first to prefer high addresses.
 

 
 

  
# 🔹 **10. Security & correctness caveats**
 
 
- File truncation after a MAP_PRIVATE mapping can SIGBUS when accessed.
 
- MAP_FIXED can overwrite existing mappings (dangerous).
 
- MAP_NORESERVE disables commit checks → process may crash later if memory really exhausted.
 
- userfaultd safe but can stall app if daemon doesn’t reply.
 
- Closing fd doesn’t unmap — VMA persists until munmap/exit.
 

  
# ✅ **Grand Mental Model**
 
 
- **Per-process:** 
 
  - fd table → fds → struct file.
 
  - mm_struct → VMA rb-tree → defines address space.
 

 
 
- **Global (per-file):** 
 
  - inode → address_space → page cache (xarray of struct pages).
 

 
 
- **Read/write:** use page cache directly, no VMA.
 
- **mmap:** uses both → connects per-process VMA to global page cache.
 
- **userfaultd:** special hook where kernel outsources fault handling to user-space.

# 🔑 Linux Page Fault Handling — Exhaustive Summary
 
A **page fault** occurs when the MMU detects an invalid or disallowed access to a virtual address. Linux then resolves it (if valid) or signals/terminates the process.
  
## 1. **Types of Page Faults**
 
 
- **Anonymous faults**: For memory not backed by a file (heap, brk, stack).
 
- **File-backed faults**: For mmap()ed files; resolved via page cache or filesystem read.
 
- **Copy-on-Write (COW)**: On first write to MAP_PRIVATE mapping.
 
- **Stack expansion faults**: Access below current stack VMA triggers VMA growth.
 
- **Special mapping faults**: For VMAs marked PFNMAP/MIXEDMAP (device memory).
 
- **Bad area faults**: Access outside valid VMA range → SIGSEGV / kernel Oops.
 

  
## 2. **Generic Fault Entry Path**
 
 
- CPU traps into kernel on fault (#PF on x86).
 
- Kernel handler checks: 
 
  - **Mode** (user vs kernel).
 
  - **Address** (valid VMA or not).
 
  - **Permissions** (read/write/exec allowed?).
 

 
 
- If resolvable → go to demand paging.
 
- Else → error path (SIGSEGV / Oops).
 

  
## 3. **Anonymous Page Faults**
 
 
- Triggered by first access to unmapped anonymous memory.
 
- Path: 
 
  1. Allocate zeroed page (alloc_zeroed_user_highpage()).
 
  2. Build new PTE (mk_pte()).
 
  3. Install with set_pte_at_notify().
 
  4. Add to reverse mapping (page_add_new_anon_rmap()).
 
  5. Insert into LRU (lru_cache_add_inactive_or_unevictable()).
 

 
 
- Pages “faulted in” lazily → **demand paging**.
 

  
## 4. **File-Backed Page Faults**
 
 
- Handled in **do_fault()**, dispatching based on fault type: 
 
  - **Read fault** → do_read_fault(). 
 
    - Reads from page cache or filesystem (filemap_fault()).
 
    - May use do_fault_around() to fault multiple nearby pages.
 

 
 
  - **Write fault MAP_PRIVATE** → do_cow_fault(). 
 
    - Triggers COW (see §5).
 

 
 
  - **Write fault MAP_SHARED** → do_shared_fault(). 
 
    - Marks page dirty; may call filesystem hook page_mkwrite().
 

 
 

 
 

  
## 5. **Copy-on-Write (COW) Faults**
 
Triggered when process writes to MAP_PRIVATE file-backed memory.
 
### do_cow_fault()
 
 
- Prepares anon_vma.
 
- Allocates new anonymous page.
 
- Copies contents from original file-backed page into new page.
 
- Installs new page in PTE.
 

 
### wp_page_copy() internals
 
 
- Allocates new page.
 
- flush_cache_page() ensures no stale cache.
 
- Builds new writable, dirty PTE.
 
- pte_clear_flush_notify() removes old mapping and flushes TLB.
 
- Reverse map updates (page_add_new_anon_rmap()).
 
- Insert new page into LRU.
 
- Decrement mapcount on old page (page_remove_rmap()).
 
- Free swap cache entry if needed.
 

 
### Edge case: PFNMAP/MIXEDMAP COW
 
 
- If source has no struct page, kernel uses __wp_page_copy_user(): 
 
  - Tries __copy_from_user_inatomic() from user address.
 
  - If fails: clears page (zero fill).
 
  - Always revalidates under page table lock.
 

 
 
- Guarantees process never sees garbage even for “special” mappings.
 

  
## 6. **TLB and Cache Synchronization**
 
 
- Critical for coherence across CPUs.
 
- Functions: 
 
  - pte_clear_flush() → clears PTE and flushes stale TLB entry.
 
  - pte_accessible() → checks if TLB flush needed (present/protnone+flush_pending).
 
  - update_mmu_cache() → syncs CPU MMU state after installing new PTE.
 

 
 
- Ordering: must clear old PTE & flush **before** decrementing mapcount to avoid page reuse races.
 

  
## 7. **Stack Expansion**
 
 
- Triggered if faulting address lies just below stack VMA with VM_GROWSDOWN.
 
- **expand_stack() → expand_downwards()**: 
 
  - Enforces mmap_min_addr (security).
 
  - Enforces stack_guard_gap (default 1MiB).
 
  - Allocates anon_vma if needed.
 
  - Acquires locks (anon_vma_lock_write(), mm->page_table_lock).
 
  - Adjusts vma->vm_start downward, updates vm_pgoff.
 
  - Updates interval trees, VMA gap, accounting stats.
 

 
 
- **acct_stack_growth()** checks: 
 
  - RLIMIT_AS and RLIMIT_DATA.
 
  - RLIMIT_STACK.
 
  - RLIMIT_MEMLOCK (if mlockall() used).
 
  - Security hooks and overcommit.
 

 
 
- If checks fail → -ENOMEM, else stack grows.
 

  
## 8. **Bad Area Fault Handling**
 
If no valid VMA covers faulting address:
 
 
- **Kernel mode**: triggers Oops (page_fault_oops()).
 
- **User mode**: sends SIGSEGV.
 
- Code path: __bad_area_nosemaphore().
 
- Sanitization: 
 
  - sanitize_error_code() ensures user faults on kernel addresses are always reported as protection faults (X86_PF_PROT).
 

 
 
- Logging: 
 
  - show_signal_msg() prints kernel log (PID, IP, SP, address, error code, opcodes) if unhandled SIGSEGV.
 

 
 

  
## 9. **Special Mappings**
 
Mappings not backed by normal struct pages:
 
 
- **PFNMAP** (VM_PFNMAP): 
 
  - Maps raw PFNs linearly to userspace.
 
  - Not refcounted, no reverse map.
 
  - Always “special” unless COWed.
 

 
 
- **MIXEDMAP** (VM_MIXEDMAP): 
 
  - Can contain both struct pages and PFN-backed entries.
 
  - More flexible, but slower and more complex.
 

 
 
- **pte_special bit**: 
 
  - Marks PTE as “special”; vm_normal_page() returns NULL for these.
 

 
 
- Helper functions: 
 
  - vm_normal_page() → resolves PTE to struct page unless special.
 
  - remap_pfn_range_notrack() → installs PFN mappings into page tables, sets special VMA flags (VM_IO, VM_PFNMAP, VM_DONTEXPAND, VM_DONTDUMP).
 

 
 
- Uses: device drivers mapping hardware memory into userland.
 

  
## 10. **Unified Fault Outcomes**
 
When CPU triggers page fault:
 
 
1. **Address lookup**: Is there a VMA covering the fault? 
 
  - No → Bad area handling (SIGSEGV / Oops).
 

 
 
2. **Permissions check**: Access allowed (read/write/exec)? 
 
  - No → SIGSEGV or PKU error.
 

 
 
3. **VMA type**: 
 
  - Anonymous → demand-zero page.
 
  - File-backed → read / COW / shared fault.
 
  - Stack → expand downwards if allowed.
 
  - Special (PFNMAP/MIXEDMAP) → custom path.
 

 
 
4. **PTE install**: 
 
  - Build new PTE, flush old entry, update reverse maps, insert into LRU.
 

 
 
5. **Return to user** if resolved.
 

  
# 📌 Key Insights
 
 
- **Demand paging** = lazy allocation on first access.
 
- **COW** = protects MAP_PRIVATE until first write → then copies.
 
- **Stack growth** = automatic, bounded by rlimits + guard gap.
 
- **TLB flush order** = crucial to prevent races with old mappings.
 
- **Bad faults** = SIGSEGV in userland, Oops in kernel.
 
- **Special mappings** = device memory mappings bypass normal VM.

File-backed faults → mmap()ed files, demand-read.

Copy-on-Write (COW) → MAP_PRIVATE write faults.

Stack expansion → VM_GROWSDOWN triggers VMA growth.

Special mappings → PFNMAP/MIXEDMAP (device memory).

Bad area → Access outside valid VMA → SIGSEGV/Oops.

2. Generic Fault Entry Path
CPU raises #PF (x86) → kernel enters page fault handler.

Kernel checks:

Mode: user vs kernel fault.

VMA: is there one covering the address?

Permissions: does access type match?

If valid → resolve; else → SIGSEGV (user) / Oops (kernel).

3. Anonymous Page Faults
On first access:

Allocate zeroed page (alloc_zeroed_user_highpage()).

Build PTE (mk_pte()), install (set_pte_at_notify()).

Update reverse map (page_add_new_anon_rmap()).

Insert into LRU (lru_cache_add_*).

Implements demand paging.

4. File-Backed Page Faults
In do_fault():

Read → filemap_fault(), fetch from page cache or disk.

Write MAP_PRIVATE → do_cow_fault() (COW).

Write MAP_SHARED → do_shared_fault(), dirty + FS hooks.

May prefetch nearby pages (fault_around).

5. Copy-on-Write (COW)
On first write to MAP_PRIVATE mapping:

Allocate new anonymous page.

Copy old contents → new page.

Install writable PTE.

Flush old mapping (TLB/cache).

Update reverse map + LRU.

Edge cases:

PFNMAP/MIXEDMAP → no struct page; kernel copies via __copy_from_user_inatomic() or zero-fills.

6. TLB & Cache Synchronization
Must keep CPU caches, TLBs, and page tables consistent.

Key ops:

pte_clear_flush() → clear PTE + flush old entry.

update_mmu_cache() → update arch-specific MMU state.

Ordering rule: clear + flush before reusing/freeing page.

7. Stack Expansion
If fault below stack VMA:

expand_stack() → grow VMA downward.

Enforces:

mmap_min_addr (security).

stack_guard_gap (default ~1 MB).

Resource limits (RLIMIT_STACK, RLIMIT_AS, etc.).

Updates VMAs (rb-tree, interval tree, accounting).

8. Bad Area Faults
No valid VMA:

User mode → SIGSEGV.

Kernel mode → Oops.

Code paths sanitize error codes (avoid leaking kernel addresses).

Logs unhandled faults (show_signal_msg()).

9. Special Mappings
PFNMAP (VM_PFNMAP) → linear map of raw PFNs, no struct page.

MIXEDMAP (VM_MIXEDMAP) → mixture of struct-page + PFN.

pte_special → marks PTEs not backed by normal pages.

Installed with remap_pfn_range_notrack().

Common in device drivers exposing hardware memory.

10. Unified Flow — Fault Resolution
CPU traps (#PF).

Kernel locates VMA.

No VMA → bad area.

Check permissions.

Dispatch by VMA type:

Anonymous → demand-zero page.

File-backed → read / COW / shared.

Stack → expand if allowed.

Special → device mapping rules.

Build + install new PTE.

Flush TLB if needed.

Resume execution.

Demand paging → lazy allocation on use.

COW → MAP_PRIVATE efficiency: copy only on first write.

Stack growth → automatic but bounded (rlimits + guard).

TLB flush ordering → critical to avoid stale entries.

Bad faults → SIGSEGV (user), Oops (kernel).

Special mappings → bypass normal VM rules for device memory.

📘 Linux Memory Unmap, TLB Flush & Freeing Pipeline — Exhaustive Summary


---

1. Reverse Mapping Motivation

When reclaiming or migrating memory, the kernel works at the folio level.

To unmap a folio, it must discover which VMAs map it.

This “reverse mapping” is the opposite of normal page tables:

Forward mapping: virtual → physical (via PTE).

Reverse mapping: physical → all VMAs pointing to it.


VMAs are dynamic (split, merged, forked), so we can’t store a simple list per folio.

Solution:

File-backed folios → folio->mapping = address_space.

Anonymous folios → folio->mapping = anon_vma.




---

2. Unmapping Path (Reclaim, munmap, etc.)

High-level functions

1. unmap_vmas(tlb, vma, start, end)

Iterates VMAs in [start,end).

Notifies mmu notifiers (KVM, etc.).

Calls unmap_single_vma().



2. unmap_single_vma()

Clamps range to [vma->vm_start, vm_end).

Handles special PFNMAP VMAs separately.

Calls unmap_page_range().



3. unmap_page_range()

Walks page tables downwards:

PGD → P4D → PUD → PMD → PTE.


At each level: skip empty/bad, recurse deeper.

At PMD level: handle THPs, otherwise call zap_pte_range().




zap_pte_range()

Core loop where PTEs are actually cleared:

Lock PTE page (pte_offset_map_lock).

For each PTE:

If present:

Clear entry (ptep_get_and_clear_full).

Update reverse map: page_remove_rmap() (anon/file).

Mark dirty/accessed as needed.

Add to mmu_gather_batch for deferred free.


If swap/migration entry → handled separately.



On completion:

Pages batched for free.

TLB entries marked for flush.

3. Reverse Mapping Removal

page_remove_rmap(page, vma, compound)

Decrement _mapcount.

If last mapping removed → candidate for free.

Adjusts per-mm RSS counters.


Distinction:

File-backed → page_remove_file_rmap().

Anon-backed → page_remove_rmap().

4. Page Table Freeing

Once mappings are gone, page table structures themselves are freed:

free_pgtables()

Unlinks VMA from anon/file reverse mappings.

Calls free_pgd_range().


free_pgd_range() → free_p4d_range() → free_pud_range() → free_pmd_range() → free_pte_range()

Walks down levels.

Clears entries, schedules free with tlb_remove_table().

Actual freeing deferred until safe TLB flush.



👉 Only page tables are freed here, not data pages (those freed via rmap + zap).


---

5. TLB Flushing Machinery

mmu_gather

Collects pages + tables to free.

Defers TLB flushes until the end.

Avoids repeated flushes per PTE.


Flush flow

1. tlb_finish_mmu()

Called after unmap.

Calls tlb_flush_mmu().



2. tlb_flush_mmu()

Splits into:

tlb_flush_mmu_tlbonly() → flush TLBs.

tlb_flush_mmu_free() → free batched pages/tables.





Local vs Remote

Local flush (flush_tlb_mm_range, flush_tlb_local):

Performed on current CPU.


Remote shootdown (native_flush_tlb_multi):

Send IPIs to other CPUs in mm_cpumask(mm).

Ensures all CPUs drop stale translations.



Generational Tracking

Each mm has mm_tlb_gen.

Each CPU tracks local_tlb_gen.

A flush brings CPU’s local gen up to mm_tlb_gen.

Prevents redundant flushes.


Partial vs Full Flush

Partial allowed if:

New gen = local gen + 1.

New gen == mm’s global gen.


Else full flush is safer.

Partial → flush_tlb_one_user() loop.

Full → flush_tlb_local() (reload CR3).



---

6. Freeing Physical Pages

Flow

tlb_flush_mmu_free() → tlb_batch_pages_flush() → free_pages_and_swap_cache() → release_pages() → free_unref_page_list().


Key pieces

free_pages_and_swap_cache()

Drop from swapcache (free_swap_cache()).

Calls release_pages().


release_pages()

Batched put_page().

If refcount=0:

Remove from LRU list.

Clear mlocked or other flags.

Free via free_unref_page_list().



Optimized to reduce IRQ-off lock hold time (lock_batch).



---

7. Lazy TLB Mode

enter_lazy_tlb(mm, tsk)

If CPU already on init_mm → return.

Else mark per-CPU is_lazy = true.


Meaning

Kernel threads “borrow” a user mm instead of doing a costly switch_mm().

TLB may contain stale entries → acceptable, spurious kernel faults handled by spurious_kernel_fault().


Exiting Lazy Mode

switch_mm_irqs_off() when scheduler switches back to a real mm.

Clears is_lazy, reloads CR3 if needed.


👉 Optimization: avoids frequent TLB flushes when kernel threads run briefly.


---

⚡ End-to-End Pipeline

1. Reclaim/unmap starts

try_to_unmap() → unmap_vmas().



2. PTEs zapped

zap_pte_range() clears PTEs.

Updates rmap (page_remove_rmap).

Pages batched for freeing.



3. Page tables freed

free_pgtables() recursively frees PGD→PTE.



4. TLBs flushed

tlb_finish_mmu() performs batched flush.

Local flush via flush_tlb_func().

Remote CPUs handled via IPIs (native_flush_tlb_multi).

Generational scheme ensures no redundant flushes.



5. Pages physically freed

tlb_batch_pages_flush() → free_pages_and_swap_cache() → release_pages().

Drop from LRU, swap, free via allocator.



6. Lazy TLB optimization

Kernel threads may skip real TLB reloads.

Marked with enter_lazy_tlb().

Spurious faults expected, cleaned up.

Cleared in switch_mm_irqs_off().

The Linux unmap pipeline works by zapping PTEs and reverse maps, freeing page tables, performing batched TLB flushes across CPUs with generational tracking, and finally releasing pages to the allocator — with lazy TLB mode as an optimization to avoid unnecessary TLB reloads for kernel threads.

# 📚 **Exhaustive Summary — madvise() Internals and Memory Attribute Manipulation**
  
## 🔹 1. Context: Memory Attribute Manipulation APIs
 
We first positioned madvise() as part of the broader set of Linux memory attribute syscalls:
 
 
- **mlock/mlock2/munlock** → Lock/unlock pages in RAM, prevent swapping.
 
- **mprotect** → Change permissions (read/write/exec).
 
- **mremap** → Resize/relocate mappings (like realloc() in userland).
 
- **madvise** → Give kernel hints about memory usage patterns.
 

 
Among these, **madvise()** is the most flexible and “advisory” in nature.
  
## 🔹 2. Kernel Flow of madvise()
 
### **do_madvise()**
 
 
- Validates arguments (start, len, advice).
 
- Decides locking type: 
 
  - Some hints only need mmap_lock **read lock** (e.g. access pattern hints).
 
  - Others require **write lock** (e.g. MADV_DONTNEED, which unmaps pages).
 

 
 
- Calls **madvise_walk_vmas()** to traverse all VMAs covering the range.
 

  
### **madvise_walk_vmas()** (Listing 8-73)
 
 
- Iterates across **all VMAs** spanning the [start, end) range.
 
- Uses find_vma_prev() to locate the first VMA.
 
- For each VMA: 
 
  - If there’s a gap → set error -ENOMEM.
 
  - Clamp region: tmp = min(vma->vm_end, end).
 
  - Call visit() callback (in our case, madvise_vma_behavior()) on [start, tmp).
 
  - Advance start = tmp.
 

 
 
- Stops when range fully covered or error occurs.
 
- Returns -ENOMEM if unmapped gaps found, but still applies advice to valid VMAs.
 

 
👉 **Purpose**: Safe traversal with gap handling, ensuring each VMA gets processed.
  
### **madvise_vma_behavior()** (Listing 8-74)
 
 
-  
Core function applying the **specific behavior** (MADV_*) to a given VMA region.
 
 
-  
Steps:
 
 
  1. Copy new_flags = vma->vm_flags.
 
  2. Switch-case over behavior (MADV_*).
 
  3. For each case: 
 
    - Some call helper functions (e.g. madvise_remove(), madvise_willneed(), madvise_pageout(), ksm_madvise(), hugepage_madvise()).
 
    - Others directly update new_flags (e.g. set/clear VM_DONTFORK, VM_SEQ_READ).
 

 
 
  4. If VMA flags changed → call **madvise_update_vma()** to update them safely.
 

 
 
-  
Error handling:
 
 
  - Returns -EAGAIN if kernel resources (e.g., slab) temporarily unavailable.
 
  - Converts -ENOMEM from helpers into -EAGAIN.
 

 
 

 
👉 **Purpose**: Encapsulates all MADV behaviors and translates them into VMA changes or actions.
  
### **Supported MADV Behaviors**
 
Handled in madvise_vma_behavior():
 
 
-  
**Page lifecycle hints**:
 
 
  - MADV_REMOVE → discard file-backed range.
 
  - MADV_DONTNEED → drop pages, data lost if anonymous.
 
  - MADV_DONTNEED_LOCKED → drop but keep locked pages stable.
 
  - MADV_FREE → mark anon pages discardable on pressure.
 
  - MADV_PAGEOUT → reclaim pages now.
 
  - MADV_COLD → mark pages cold for reclaim.
 

 
 
-  
**Population / prefetch**:
 
 
  - MADV_WILLNEED → prefetch.
 
  - MADV_POPULATE_READ / WRITE → fault-in pages immediately.
 

 
 
-  
**Access patterns**:
 
 
  - MADV_NORMAL → default.
 
  - MADV_RANDOM → disable readahead.
 
  - MADV_SEQUENTIAL → aggressive readahead.
 

 
 
-  
**Fork behavior**:
 
 
  - MADV_DONTFORK → exclude from child.
 
  - MADV_DOFORK → include in child.
 
  - MADV_WIPEONFORK → zero-out on fork.
 
  - MADV_KEEPONFORK → preserve on fork.
 

 
 
-  
**Dumping behavior**:
 
 
  - MADV_DONTDUMP → exclude from core dump.
 
  - MADV_DODUMP → include in core dump.
 

 
 
-  
**Advanced policies**:
 
 
  - MADV_MERGEABLE / UNMERGEABLE → KSM.
 
  - MADV_HUGEPAGE / NOHUGEPAGE → THP.
 

 
 

  
### **madvise_update_vma()** (Listing 8-75)
 
Handles actual update of vma->vm_flags and anon_vma if needed.
 
Steps:
 
 
1. If nothing changes (flags and anon_vma same) → return immediately.
 
2. Try **merge**: attempt to merge with adjacent VMAs (vma_merge()) if flags match.
 
3. If cannot merge, must **split VMA** (__split_vma()) so only the affected range is updated. 
 
  - Check mm->map_count < sysctl_max_map_count.
 
  - If exceeded, return -ENOMEM.
 

 
 
4. Apply new flags: vma->vm_flags = new_flags.
 
5. If anonymous → update anon_vma name via replace_anon_vma_name().
 
6. Return success.
 

 
👉 **Purpose**: Safely mutate VMAs, minimizing fragmentation (merge if possible, split otherwise).
  
## 🔹 3. Error Semantics
 
 
- -EINVAL: invalid advice or unsupported region.
 
- -ENOMEM: if too many VMAs (map_count exceeded) → converted to -EAGAIN.
 
- -EAGAIN: temporary kernel resource shortage.
 
- -EFAULT: invalid address.
 
- 0: success.
 

  
## 🔹 4. Key Insights
 
 
- **madvise() is advisory** → kernel may ignore hints.
 
- It **walks all VMAs** in the range and applies behavior region by region.
 
- **Behavior-specific helpers**: reclaim (madvise_pageout), discard (madvise_remove), prefetch (madvise_willneed), policy toggles (ksm_madvise, hugepage_madvise).
 
- **VMA updates** involve splitting/merging to preserve consistent memory layout.
 
- Crucial for **performance tuning** (databases, JITs, HPC, real-time apps).

# 📘 Exhaustive Summary of Linux Writeback & Dirty Throttling
 
Linux must balance:
 
 
- **Dirtying pages (foreground)** → apps writing to page cache.
 
- **Cleaning pages (background)** → flusher threads writing them back to disk.
 
- **Memory & bandwidth limits** → avoid stalling, avoid I/O storms.
 

 
This balance is achieved with the **writeback + dirty throttling subsystem**.
  
## 1. **Dirty Tracking**
 
 
- When a page (folio) in page cache is modified → it’s marked **dirty**.
 
- **Tracking mechanisms**: 
 
  - PAGECACHE_TAG_DIRTY → tagged in inode’s xarray.
 
  - Inode itself marked dirty → added to bdi_writeback->b_dirty list.
 

 
 
- If **CONFIG_CGROUP_WRITEBACK** is enabled → dirty pages are tracked per-cgroup as well.
 

  
## 2. **Writeback Lifecycle**
 
### (a) Starting I/O
 
 
-  
**folio_clear_dirty_for_io()**:
 
 
  - Clears folio dirty flag.
 
  - Makes PTEs read-only → new writes cause page faults (re-dirty safely).
 

 
 
-  
**__folio_start_writeback()**:
 
 
  - Marks folio under writeback (PAGECACHE_TAG_WRITEBACK).
 
  - If first folio of inode → put inode on superblock’s writeback list.
 

 
 

 
### (b) Completing I/O
 
 
- **__folio_end_writeback()**: 
 
  - Clears writeback flag, removes tags.
 
  - If no more folios dirty for inode → inode removed from writeback list.
 
  - Updates bandwidth stats for feedback control.
 

 
 

  
## 3. **Flusher Threads & Triggers**
 
 
- Global writeback workqueue (bdi_wq) runs background flusher threads.
 
- **Wakeups**: 
 
  - **wb_wakeup_delayed()** → every vm.dirty_writeback_centisecs (default 5s).
 
  - **wb_wakeup()** → immediate (e.g., sync/fsync, dirty_ratio exceeded).
 

 
 
- **Tasks** (wb_workfn): 
 
  - Move inodes from b_dirty → b_io.
 
  - Call FS ->writepages() or generic_writepages().
 
  - Process dirty folios via write_cache_pages().
 

 
 

  
## 4. **Dirty Balancing / Throttling**
 
### (a) Dirty Thresholds
 
 
- Controlled by **vm.dirty_ratio, vm.dirty_bytes** (global caps).
 
- **vm.dirty_background_ratio, vm.dirty_background_bytes**: background flusher thresholds.
 
- **domain_dirty_limits()**: computes global + background thresholds.
 
- **__wb_calc_thresh()**: divides thresholds among backing devices (bdi) proportional to bandwidth.
 

 
### (b) balance_dirty_pages() (Listings 10-97 → 10-101)
 
Core loop run by tasks that dirty pages:
 
 
1. **Setup** dirty_throttle_control (gdtc) with current dirty stats.
 
2. **Initial checks**: 
 
  - If dirty > bg_thresh and no writeback running → start background writeback.
 
  - In **laptop mode** → delay until higher thresholds.
 

 
 
3. **Freerun case**: 
 
  - If well below thresholds → compute dirty_poll_interval() and return quickly.
 

 
 
4. **Statistics gathering**: 
 
  - Compute per-bdi limits (wb_dirty_limits).
 
  - Set dirty_exceeded if global or bdi threshold breached.
 
  - Compute pos_ratio → how close to threshold.
 
  - Update bandwidth (__wb_update_bandwidth).
 
  - Update dirty rate limit (wb_update_dirty_ratelimit).
 

 
 
5. **Throttling**: 
 
  - Compute per-task dirtying rate limit (task_ratelimit).
 
  - Determine pause time based on how many pages were dirtied.
 
  - Clamp pause between **min_pause (≈10ms)** and **max_pause (200ms)**.
 
  - Put task to sleep with io_schedule_timeout().
 
  - Update task-local fields (dirty_paused_when, nr_dirtied_pause).
 

 
 
6. **Exit**: 
 
  - Exit if dirty below thresholds, or signal pending, or low activity.
 
  - Otherwise loop again until balanced.
 

 
 

 
### (c) Rate Limiting Functions
 
 
- **wb_update_dirty_ratelimit()**: sets per-bdi and per-task dirtying speed.
 
- **wb_max_pause() / wb_min_pause()**: control sleep times.
 
- **dirty_poll_interval()**: avoids too-frequent global state checks.
 

  
## 5. **Writeback Chunk Size (Listing 10-102)**
 
 
- Determines how many pages to flush in one batch: 
 
  - If WB_SYNC_ALL (e.g., sync): flush all dirty pages.
 
  - Otherwise: 
 
    - ≤ ½ second’s worth of device bandwidth.
 
    - ≤ ⅛ of dirtyable memory.
 
    - Limited by work request size.
 
    - Rounded to at least **4MB (MIN_WRITEBACK_PAGES)**.
 

 
 

 
 
- Goal: efficient batching, avoid both tiny writes and hogging.
 

  
## 6. **Background Writeback Threshold (Listing 10-103)**
 
 
- **wb_over_bg_thresh()**: decides if background flusher should keep running.
 
- Checks: 
 
  - Global dirty pages > global background threshold → yes.
 
  - Else, per-bdi dirty pages > bdi-specific background threshold → yes.
 
  - Otherwise → stop background writeback.
 

 
 

  
## 7. **wb_calc_thresh() Wrapper (Listing 10-104)**
 
 
- Thin wrapper around __wb_calc_thresh().
 
- Computes per-bdi dirty threshold using WB_RECLAIMABLE.
 
- If reclaimable > threshold → keep writeback running.

1. **Writeback lifecycle**: dirty folio → start writeback → complete writeback.
 
2. **Flusher threads**: background daemons, woken by thresholds/timers.

5. **Threshold checks**: global + per-bdi ensure fairness across devices.
 
6. **Feedback control system**: 
 
  - Producers = apps dirtying pages.
 
  - Consumers = flusher threads cleaning pages.
 
  - Controller = throttling + thresholds + bandwidth estimation.

  - Provide reclaim path for anonymous memory.
 
  - Balance memory pressure between cache and anonymous pages.
 
  - Avoid thrashing (constant I/O churn).
 

 
 

  
## **II. Swap-Out Path (Reclaim → Write to Swap)**
 
 
1.  
**Reclaim picks a folio** (from shrink_page_list).
 
 
2.  
**pageout()**:
 
 
  - Clears dirty flag (folio_clear_dirty_for_io).
 
  - Marks folio reclaimable.
 
  - Calls mapping’s writepage() → for swap, that’s swap_writepage().
 

 
 
3.  
**swap_writepage()**:
 
 
  - First tries try_to_free_swap(page) (skip if slot not needed).
 
  - Else → calls __swap_writepage().
 

 
 
4.  
**__swap_writepage()**:
 
 
  - Builds a bio request with swap slot sector.
 
  - Marks page PG_writeback.
 
  - Submits async I/O to block device.
 

 
 
5.  
**I/O Completion (end_swap_bio_write)**:
 
 
  - Clears writeback.
 
  - Marks page reclaimable.
 

 
 
6.  
**Remove Mapping**:
 
 
  - __remove_mapping() freezes refcount and removes from swap cache.
 
  - Calls __delete_from_swap_cache() → removes folio from swapper’s xarray.
 
  - Calls put_swap_page() to decrement swap slot usage.
 

 
 
7.  
**Free Memory**:
 
 
  - Once unmapped and unreferenced → returned to free pool.
 

 
 

  
## **III. Swap-In Path (Page Fault → Bring Back)**
 
 
1.  
**Fault occurs**: PTE marked non-present but contains swp_entry_t.
 
 
  - Handler: do_swap_page().
 

 
 
2.  
**Check swap cache**:
 
 
  - If lookup_swap_cache(entry) succeeds → reuse page (minor fault).
 
  - If not found → allocate new page.
 

 
 
3.  
**Read from Swap**:
 
 
  - Allocate page, mark as swap-backed.
 
  - Insert into swap cache.
 
  - Call swap_readpage() or swapin_readahead().
 

 
 
4.  
**Synchronize**:
 
 
  - Wait for page lock if already being faulted in.
 

 
 
5.  
**Edge Cases**:
 
 
  - Exclusive mapping check for write faults.
 
  - Handle swapoff, writeback, or races.
 
  - SIGBUS if page can’t be read.
 

 
 
6.  
**Install Page**:
 
 
  - Free swap slot (swap_free).
 
  - Update counters (MM_ANONPAGES++, MM_SWAPENTS--).
 
  - Create new PTE, map into process.
 
  - Add to reverse mapping (rmap).
 
  - Unlock page.
 

 
 

  
## **IV. Swap Readahead (Optimization)**
 
Linux tries to **avoid repeated faults** by preloading more pages.
 
### **1. Cluster Readahead**
 
 
- Based on **physical swap slots**.
 
- Trigger: cluster of adjacent slots around fault.
 
- Controlled by page_cluster (boot-time tunable).
 
- Example: with page_cluster=3 → fetch 8 slots.
 
- Good for HDDs (sequential disk reads are cheap).
 

 
### **2. VMA Readahead**
 
 
-  
Based on **virtual addresses inside same VMA**.
 
 
-  
Trigger: access pattern (forward, backward, or random).
 
 
-  
Tracks state in struct vma_swap_readahead:
 
 
  - win = window size.
 
  - offset = fault position inside window.
 
  - nr_pte = number of PTEs.
 
  - ptes = pointer to first PTE in range.
 

 
 
-  
Algorithm (swap_ra_info()):
 
 
  1. Determine window size with __swapin_nr_pages().
 
  2. Clamp to max size (SWAP_RA_ORDER_CEILING = 32 pages).
 
  3. Use PFN clamping (swap_ra_clamp_pfn()) to stay inside VMA + same PMD.
 
  4. Loop through PTEs: 
 
    - Skip invalid entries.
 
    - Prefetch with __read_swap_cache_async().
 
    - Issue I/O with swap_readpage().
 
    - Mark extras as PG_readahead.
 

 
 

 
 
-  
Better for SSDs/random workloads.
 
 

  
## **V. Window Size Calculation (Heuristics)**
 
### **swapin_nr_pages() / __swapin_nr_pages()**
 
 
- Baseline = **hits + 2** (hits = number of previously useful readahead pages).
 
- If no hits → only 1 page.
 
- If sequential access → round up to next power-of-two (≥4).
 
- Cap at max_pages (from page_cluster).
 
- Don’t shrink too fast: at most halve last_ra.
 

 
### **swap_setup()**
 
 
- Initializes page_cluster at boot: 
 
  - Small RAM (<16 MB): cluster = 2 (max 4 pages).
 
  - Larger RAM: cluster = 3 (max 8 pages).
 

 
 
- Tunable at runtime via /proc/sys/vm/page-cluster.
 

  
## **VI. PFN Clamping (swap_ra_clamp_pfn())**
 
Ensures readahead stays valid:
 
 
- **Start PFN** = max(requested left bound, VMA start, PMD start).
 
- **End PFN** = min(requested right bound, VMA end, PMD end).
 
- Uses PMD_MASK and PMD_SIZE to align to page table boundaries.
 
- Prevents overrunning VMA or page table.

🧠 Full Summary: Linux OOM Killer & Reaper Internals


---

1. Why OOM Happens

Virtual vs Physical memory mismatch

malloc()/mmap() only reserve virtual space.

Physical pages allocated lazily (on access).

If no memory available at page fault → OOM.


Zones & Watermarks

Memory split into zones (DMA, NORMAL, etc.).

Watermarks:

WMARK_HIGH = healthy

WMARK_LOW = background reclaim (kswapd)

WMARK_MIN = allocations must reclaim directly


If even direct reclaim fails → OOM.


Overcommit

Linux allows allocating more virtual memory than available physical (/proc/sys/vm/overcommit_memory).

When commitments can’t be fulfilled → OOM.




---

2. OOM Killer Trigger

Triggered when kernel can’t satisfy allocations and reclaim fails.

Manual trigger: SysRq+F or echo f > /proc/sysrq-trigger.



---

3. Victim Selection

Done in oom_badness():

Score = proportional to resident memory usage.

Adjusted by /proc/$pid/oom_score_adj (range -1000 to +1000).

-1000: never kill

1000: always kill



Edge cases:

Already exiting tasks skipped.

MMF_OOM_SKIP set → skipped.

vfork children skipped (no independent mm).

oom_score_adj = OOM_SCORE_ADJ_MIN → immune.




---

4. Victim Killing

Happens in oom_kill_process():

1. Lock task.


2. If task will free memory → mark victim (mark_oom_victim()), queue for reaping (queue_oom_reaper()), unlock.


3. Send SIGKILL via do_send_sig_info().


4. Log details: RSS, anon/file/shmem usage, UID, oom_score_adj.


5. Unlock + release references.



mark_oom_victim():

Marks victim with MMF_OOM_VICTIM.

Increments mm_count.

Updates oom_victims counter.

Ensures only one victim per mm.




---

5. OOM Reaper Role

Problem: killed tasks may not exit quickly (e.g., stuck in kernel).

Solution: dedicated kernel thread (oom_reaper) forcibly frees victim’s memory.

Benefits: ensures allocator makes progress, prevents deadlock.



---

6. OOM Reaper Internals

Thread init: started in oom_init() as kernel thread.

queue_oom_reaper():

Adds victim to oom_reaper_list.

Uses OOM_REAPER_DELAY (2s) → lets victim exit gracefully before reaping.

Sets MMF_OOM_REAP_QUEUED.


wake_oom_reaper(): wakes reaper thread from wait queue.

oom_reaper() loop:

Waits until victim queued.

Calls oom_reap_task().




---

7. oom_reap_task()

Tries to reclaim victim’s address space:

Up to MAX_OOM_REAP_RETRIES (10).

Sleeps 0.1s between retries.

Calls oom_reap_task_mm() each time.


If fails consistently → sets MMF_OOM_SKIP.

Removes mm from list → no more reaping.



---

8. oom_reap_task_mm()

Wrapper for actual reclaim:

Acquire mmap_read_trylock() (non-blocking).

Check MMF_OOM_SKIP again.

Call __oom_reap_task_mm() if ok.

Log memory freed (anon-rss, file-rss, shmem-rss).

Release lock.




---

9. __oom_reap_task_mm()

Core of reaping logic:

Set MMF_UNSTABLE → marks mm unstable (future accesses SIGBUS).

Iterate victim’s VMAs:

Skip hugetlb (VM_HUGETLB) and PFNMAP mappings (special).

Only reap anonymous private pages.

File-backed pages skipped (already reclaimable).


Use tlb_gather_mmu() + unmap_page_range() + tlb_finish_mmu() to unmap + flush TLB.

Free pages immediately.




---

10. exit_mmap() and OOM

When process exits normally:

exit_mmap() releases mappings.

If OOM victim: also sets MMF_OOM_SKIP.

Ensures OOM reaper won’t touch it anymore.




---

11. Key Flags Recap

MMF_OOM_VICTIM → process marked as OOM victim.

MMF_OOM_SKIP → skip this mm (already handled or unreapable).

MMF_UNSTABLE → mm unstable; accesses cause SIGBUS.

MMF_OOM_REAP_QUEUED → queued for reaping.

🔹 6. Shared Memory Mechanisms

Four main mechanisms:

(a) System V Shared Memory

Oldest IPC method.

Use shmget(key, size, IPC_CREAT|0666) → ID.

Attach with shmat(id, NULL, 0).

Server creates with IPC_CREAT, client attaches with same key.

Still works but legacy.


(b) POSIX Shared Memory

Successor to SysV, simpler API.

shm_open("/name", O_CREAT|O_RDWR, 0666) → fd in /dev/shm/name.

ftruncate(fd, size).

mmap(fd, MAP_SHARED).

shm_unlink("/name") to remove.

Cleaner, uses normal file APIs.


(c) Anonymous Shared Memory

mmap(NULL, size, PROT_READ|WRITE, MAP_SHARED|MAP_ANON, -1, 0).

Parent + forked child automatically share memory (no file, no name).

Backed by tmpfs internally.

Simple for parent-child IPC.


(d) memfd

Most modern & flexible.

memfd_create("name", MFD_ALLOW_SEALING) → RAM-backed file descriptor.

ftruncate(fd, size) to set size.

Seals with fcntl(F_ADD_SEALS, …) → prevent grow/shrink/changes.

Mapped with mmap(fd, MAP_SHARED).

File descriptor appears under /proc/<pid>/fd/<n> and can be passed via UNIX socket.

Used widely (systemd, Wayland).

📖 Linux Memory Interfaces, OOM, Procfs, Tunables & Shared Memory — Full Summary
1. User ↔ Kernel Memory Interfaces
Users don’t manipulate page tables directly. They use syscalls, libc, and procfs/sysfs interfaces.

Syscalls & libc:

mmap(), munmap(), msync() → map/unmap/sync memory (file or anonymous).

brk(), sbrk() → grow/shrink heap region.

malloc() → glibc allocator, backed by mmap/brk.

mprotect() → change protections (R/W/X).

mremap() → resize/move mappings.

mlock()/munlock() → pin/unpin memory (unevictable LRU).

madvise() → give kernel hints (sequential, dontneed, hugepage, mergeable).

mincore() → check residency of pages.

userfaultfd → delegate page faults to userspace.

ptrace() / process_vm_readv / writev → debugger & cross-process memory copy.

File-system interfaces:

/proc/$pid/maps → per-process VMA list.

/proc/$pid/smaps & smaps_rollup → per-VMA RSS, PSS, swap, etc.

/proc/$pid/pagemap → VA → PFN mapping + flags.

/proc/kpageflags, /proc/kpagecount → global page state and mapping counts.

/proc/meminfo, /proc/vmstat, /proc/zoneinfo, /proc/buddyinfo → system memory stats.

2. mmap() Variants
MAP_SHARED → shared mappings, writes visible to others and synced to file.

MAP_SHARED_VALIDATE → like above, validates flags.

MAP_PRIVATE → copy-on-write, not propagated to file.

MAP_FIXED → force exact VA (can overwrite).

MAP_FIXED_NOREPLACE → safe, fails if VA used.

MAP_ANON|MAP_SHARED → anonymous shared, e.g. fork-shared memory.

3. OOM Killer Reports & Behavior
When allocations fail after reclaim:

Logs include:

Failing task, GFP mask, order.

Full task list with VM stats and oom_score_adj.

Zone info and watermarks.

Kernel backtrace of allocation site.

Victim selection:

oom_badness() computes score ≈ RSS × oom_score_adj.

oom_score_adj: -1000 (immune) to +1000 (preferred victim).

Excludes exiting tasks, vfork children.

Killing path:

oom_kill_process() sends SIGKILL.

mark_oom_victim() marks with MMF_OOM_VICTIM.

Victim queued for reaper if it doesn’t exit.

OOM Reaper:

Kernel thread forcibly reclaims anon pages if victim stalls.

oom_reap_task_mm() unmaps anon-private VMAs, frees pages.

Flags:

MMF_OOM_VICTIM = chosen victim.

MMF_OOM_SKIP = skip, already handled.

MMF_UNSTABLE = reaped, future accesses SIGBUS.

Tunables:

oom_dump_tasks (default=1) → dump all tasks in logs.

oom_kill_allocating_task → kill requester instead of worst task.

panic_on_oom: 0=normal, 1=panic if constrained, 2=panic always.

4. Page Table Introspection
/proc/$pid/pagemap → per-VA 64-bit entries:

Bits: present, swapped, soft-dirty, exclusive, file/anon.

PFN if resident.

/proc/kpageflags → page flags: referenced, active, dirty, writeback, etc.

/proc/kpagecount → number of mappings to a PFN.

5. VM Tunables (/proc/sys/vm)
Reserves:

min_free_kbytes → baseline free pages for watermarks.

lowmem_reserve_ratio → inter-zone reserves.

admin_reserve_kbytes / user_reserve_kbytes.

max_map_count → max VMAs per process.

mmap_min_addr → prevent NULL mapping.

Compaction:

compact_memory → trigger compaction manually.

compaction_proactiveness → aggressiveness of background compaction.

Writeback:

dirty_background_ratio / bytes → trigger background flush.

dirty_ratio / bytes → force task writeout.

dirty_expire_centisecs (default 30s).

dirty_writeback_centisecs (default 5s).

drop_caches → free pagecache/slabs.

Swapping:

swappiness (0–200, default 60).

page-cluster → cluster swap I/O (default=3 → 8 pages).

Overcommit:

overcommit_memory: 0=heuristic, 1=always, 2=strict.

overcommit_ratio / overcommit_kbytes → define commit limit.

Watermarks:

watermark_scale_factor, watermark_boost_factor.

zone_reclaim_mode → NUMA-local reclaim.

Per-CPU:

percpu_pagelist_high_fraction.

stat_interval, stat_refresh.

6. Shared Memory Mechanisms
(a) System V shm
API: shmget, shmat.

Identified by integer key.

Kernel cleans up on detach.

Oldest method, portable but clunky.

(b) POSIX shm
API: shm_open("/name", O_CREAT|O_RDWR), ftruncate, mmap.

Backed by tmpfs (/dev/shm).

Removed with shm_unlink.

Modern and simple, but requires global name.

(c) Anonymous Shared Memory
mmap(NULL, size, MAP_SHARED|MAP_ANON, -1, 0).

Parent and forked child share memory.

Backed by tmpfs anon in kernel.

Simple but limited to forked children.

(d) memfd
memfd_create("name", MFD_ALLOW_SEALING).

RAM-backed fd, lives until closed.

Can add seals (F_ADD_SEALS).

Passed via UNIX sockets.

Most flexible, used in systemd, Wayland.

7. Comparison of Shared Memory
Mechanism	Identifier	Backing	Lifetime	Pros	Cons
SysV shm	Key (int)	Kernel shm seg	Until detached	Old, portable	Awkward API
POSIX shm	Named (/dev/shm)	tmpfs file	Until shm_unlink	Clean, file APIs	Global name needed
Anonymous shm	None	tmpfs anon	Parent/child life	Simple, fork IPC	Not general IPC
memfd	File descriptor	tmpfs anon	Until fd close	Modern, sealing, fd passing	More setup

Syscalls (mmap, brk, mprotect, madvise) define how userland interacts with VMAs.

Procfs/sysfs expose both system-wide and per-process VM state.

OOM subsystem guarantees survival by killing + reaping a victim when reclaim fails.

Tunables (swappiness, overcommit, dirty_ratio) balance performance, responsiveness, and safety.

Shared memory has evolved: SysV → POSIX shm → anonymous → memfd.
