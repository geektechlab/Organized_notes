8.1.1 User Access
Many kernel system calls read data from or write data to userland mappings.
These occur in kernel mode from the context of the current process, so if
the specified userland virtual address is valid, either its userland mappings
will be in place or it can be faulted in as required (i.e. the address will be
marked valid in a VMA).

carefully orchestrated and tailored version of a memcpy() from kernel mode.

🔑 Accessing User Memory from the Kernel — Full Breakdown
1. Why It’s Tricky
Kernel memory: Easy — everything is part of the direct mapping (low physical memory mapped into kernel space). Kernel code can use __pa(), __va(), virt_to_folio() etc., and only kernel synchronization applies.

User memory: Hard — each process has its own independent page tables. Issues:

Kernel must walk the process’s page tables to find the folios.

Userland can unmap/remap memory while kernel is working.

The mapping can disappear underfoot.

If the kernel dereferences a bad user pointer directly → unhandled fault → kernel oops.

So: direct pointer dereferencing is forbidden. Instead, Linux provides controlled mechanisms.

2. Two Kernel Facilities
uaccess (User Access)

Lightweight access, no refcounting or locking.

Designed for fast, best-effort copy between kernel and user memory in syscalls.

If page not present → kernel can fault it in normally (like if user touched it).

Uses exception tables to recover from kernel-mode page faults.

Get User Pages (GUP)

Heavyweight mechanism: pins user pages into memory.

Increments folio refcount → ensures they won’t be freed until explicitly unpinned.

Returns references to struct folio and optionally struct vm_area_struct (VMA).

Allows fine-grained control (writable? long-term pinning? force faults? etc.).

Used in RDMA, DMA, GPU drivers, virtualization, etc.

3. User Access (uaccess) Details
When it’s used: Typical syscalls that copy buffers (e.g. read(), write(), ioctl()).

Functions:

copy_from_user(void *to, const void __user *from, unsigned long n)

copy_to_user(void __user *to, const void *from, unsigned long n)

Others: get_user(), put_user(), clear_user(), etc.

Mechanism:

Wraps memcpy() with special exception handling.

Exception tables mark “safe regions” in kernel code that may fault, and provide recovery instructions (basically: “if fault → abort and return -EFAULT instead of oopsing”).

Hence, kernel can safely attempt user memory access.

⚠️ Caveat:

No pinning → user could unmap/change the memory right after you access it.

Safe only for short-lived, single-copy transfers.

4. GUP (Get User Pages) vs. uaccess
Feature	uaccess (copy_from_user, copy_to_user)	GUP (get_user_pages)
Purpose	Lightweight memcpy-style copy	Pin and hold user pages
Refcounting	❌ none	✅ increments folio refcount
Safety from unmap	❌ may disappear after copy	✅ pinned until released
Recovery	Uses exception tables	Uses fault handling + refcounting
Use cases	Syscalls, ioctl buffer copies	RDMA, GPU, NICs, hypervisors, DMA engines
5. Caveats for Interviews (FAANG / Apple / Arm UK)
Kernel faults: Kernel-mode page faults are fatal unless handled via exception tables. User-mode faults are recoverable.

Pinning issues:

Long-term GUP pins are controversial → they can break memory management (e.g. page migration, COW, compaction). Expect questions like:
“Why are long-term GUP pins problematic for COW or page migration?”

Recent kernels are moving towards pin_user_pages() vs get_user_pages() distinction to clarify intent.

Security: Always validate user pointers (access_ok()) before touching them.

Concurrency: User can munmap() or remap while kernel is accessing memory → you must not assume stability without GUP.

DMA/IO: Device drivers must use GUP (not uaccess) when hardware is involved (because hardware might access memory asynchronously).

✅ Summary:

Kernel cannot directly dereference user pointers safely.

uaccess: Best-effort, short-term, lightweight, exception-handled copy.

GUP: Heavyweight, pins pages, returns folio + VMA, needed for DMA/long-lived ops.

Key to remember: use the right tool for the right scenario.

5. Pinning Folios
Pinning = increment folio refcount so it cannot be freed until unpinned.

Two kinds:

FOLL_GET → classic pin (increments refcount by 1).

FOLL_PIN → stronger pin (increments by GUP_PIN_COUNTING_BIAS = 2^10).

Makes it easy to detect DMA pins and avoids skew in normal refcounts.

Unpinning → gup_put_folio() or unpin_user_pages().

Why special handling?
Pinned pages can’t be migrated, reclaimed, or used for CoW.

If fork happens, CoW mappings are broken immediately.

Long-term pins (FOLL_LONGTERM) → memory migrated to unmovable blocks to avoid fragmentation.

Reclaim → skip pinned pages in shrinkers.

/procfs clear_refs → pte_is_pinned() skips clearing soft-dirty for pinned pages.

Reverse mapping → prevents clearing exclusive flags for pinned anonymous pages.

Fork → page_needs_cow_for_dma() ensures pinned pages are not CoW’d.

7. Reference Counting Tricks
Non-compound folios → bias trick (GUP_PIN_COUNTING_BIAS).

Compound folios → dedicated compound_pincount.

Function folio_maybe_dma_pinned() checks if a folio is probably pinned.

For small folios: result may be fuzzy (false positives OK).

For large folios: precise (uses compound_pincount).

Handles overflow safely by using sign bits of refcount.

pages: output array of struct page*.

vmas: optional output VMAs.

Same as get_user_pages(), but:

Sets FOLL_PIN (not FOLL_GET).

Caller must release pages via unpin_user_page().

Used for DMA / device access where pages must not migrate or be COW’d.

FOLL_GET and FOLL_PIN are mutually exclusive.

3. get_user_pages_remote()
Like get_user_pages(), but works on another process’s mm_struct.

Requires mmap_lock (read or write).

Returns pinned pages, may be less than requested.

Guarantees:

Page won’t be freed,

But mapping may change (you only know it was valid at some point).

Used for IO or device access to other process memory.

4. pin_user_pages_remote()
Same as above, but forces FOLL_PIN.

Ensures pinned memory is tracked as device-pinned, avoiding migration and CoW.

Caller must unpin.

5. Long-Term Pinning (FOLL_LONGTERM)
Requires FOLL_PIN.

Hint: memory will be pinned indefinitely (e.g. RDMA buffers).

Each folio checked with is_longterm_pinnable_page() → cannot be in ZONE_MOVABLE.

If needed, check_and_migrate_movable_pages() migrates pages to non-movable zones.

Disallows some mappings (like DAX direct access).

Ensures long-term pinned memory doesn’t fragment movable zones.

6. Follow Flags (from gup_flags)
FOLL_GET → Classic pin, increment refcount by 1.

FOLL_PIN → Strong pin, increments by bias (2¹⁰). Used for DMA.

FOLL_LONGTERM → Pages pinned for a long time, forces checks/migration.

FOLL_TOUCH → Marks page accessed (and dirty if writable).

FOLL_HWPOISON → If memory is hardware poisoned, fail with -EHWPOISON.

FOLL_DUMP → Used for core dump; skips zero pages.

FOLL_FORCE → Override VMA permissions, allow access anyway (dangerous, used by ptrace).

FOLL_NOWAIT → Don’t drop mmap_lock, don’t wait on page fault.

FOLL_NOFAULT → Don’t fault in pages, fail if not present.

FOLL_MIGRATION → If PTE invalid, try migrating instead of faulting.

FOLL_REMOTE → Access another process’s mm.

FOLL_ANON → Only allow anonymous pages.

FOLL_SPLIT_PMD → Split huge PMD mappings into base pages.

FOLL_WRITE → Require page to be writable; mark dirty.

FOLL_NUMA → If NUMA balancing hint, trigger page fault to migrate.

FOLL_TRIED → Set if fault retry attempted.

FOLL_FAST_ONLY → Used by fast variants; prevents fallback to slow path.

__get_user_pages_remote()

Core walker for remote mm.

Wrapper around _get_user_pages_locked().

Saves allocation flags with memalloc_pin_save(), disables __GFP_MOVABLE.

Loops until pages are pinned or fails.

check_and_migrate_movable_pages()

Iterates pages, checks if pinnable.

Migrates pages if required.

Returns error if migration fails.

FOLL_GET = traditional refcount.

FOLL_PIN = bias accounting for DMA, prevents silent misuse.

FOLL_LONGTERM is critical because long pins can break kernel memory management (migration, compaction, CoW).

Remote variants differ only by mm argument (can operate on another process’s address space).

Iterates across addresses → fetches each page.

Step: VMA handling

3. check_vma_flags() — Permission + Sanity Checks
Rejects if:

VM_IO or VM_PFNMAP (device memory/raw mapping).

Anonymous-only requirement (FOLL_ANON) fails.

Write requested (FOLL_WRITE) but VMA doesn’t allow it.

Not COW-safe (Copy-on-Write restrictions).

VMA lacks VM_READ and FOLL_FORCE not set.

Arch-specific access check (arch_vma_access_permitted) fails.

4. Walking Page Tables
GUP walks from top to bottom (PGD → P4D → PUD → PMD → PTE).
At each level, if entry missing or invalid, it may:

Call no_page_table() (when no entry exists).

Call faultin_page() (to trigger page fault + allocate).

Retry if needed.

a) follow_page_mask()
Entry point → starts at PGD level.

Calls into follow_p4d_mask().

b) follow_p4d_mask()
Uses p4d_offset() to locate P4D entry.

If p4d_none() or p4d_bad() → no_page_table().

c) follow_pud_mask()
Uses pud_offset().

If pud_none() or pud_bad() → no_page_table().

d) follow_pmd_mask()
Uses pmd_offset().

Reads PMD entry (READ_ONCE()).

If invalid:

Return no_page_table().

If transparent hugepage (pmd_trans_huge) or migration entry, handled specially (out of scope here).

Otherwise → go to follow_page_pte().

e) follow_page_pte()
Uses pte_offset_map_lock() to safely access the PTE with spinlock.

Validates PTE:

If not present → may retry or return no_page.

If FOLL_NUMA and pte_protnone() → also treat as no page.

If all good → calls vm_normal_page() → resolves struct page.

5. no_page_table() Special Case
Triggered if no page table entry exists.

For core dumps:

Avoid allocating unnecessary page tables.

Returns error so kernel can skip handling gaps in memory dumps.

6. Fault Handling
If page not found, faultin_page() is called:

May return retry signals (-EBUSY, -EAGAIN).

May return fatal errors (-ENOMEM, -EFAULT, -EHWPOISON).

Retries allowed depending on flags.

Reschedules (cond_resched()) to avoid soft lockups.

Aborts if fatal signal pending (like SIGKILL).

7. Key Flags
FOLL_GET: Increment refcount → page won’t be freed.

FOLL_PIN: Stronger guarantee than FOLL_GET, must unpin later (unpin_user_page).

FOLL_FORCE: Force access ignoring normal permissions (used by ptrace).

FOLL_WRITE: Ensure page is writable (may trigger COW).

FOLL_ANON: Ensure page is anonymous memory only.

FOLL_NUMA: Allow NUMA balancing faults.

8. Return Path
On success: returns number of pages pinned.

On error: negative errno (-EFAULT, -ENOMEM, -EAGAIN, etc.).

If retryable → loops back.

If pinned pages exist but later fail → may partially succeed.

Error Handling: Retry on transient errors, exit on fatal ones.

Flags: Control behavior (GET vs PIN, WRITE, FORCE, NUMA).
