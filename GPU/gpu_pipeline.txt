Why Triangles as primitives?
	Any 3D surface can be broken into triangles (smallest convex polygon). GPUs are optimized for triangles → guaranteed planar, easy to interpolate.
		Example: Cube face (a quad) is split into 2 triangles.

Spaces (coordinate transformations)
	Model Space – cube’s local coordinates (corner = (1,1,1)).
	World Space – after placing cube in scene (cube at (10,0,5)).
	Camera/View Space – transform relative to camera (cube appears in front).
	Clip/Screen Space – mapped to 2D screen pixels.

-------------

In GPUs threads are grouped into warps (usually 32 threads) and executes the same instruction at the same time across different data (SIMD: Single Instruction Multiple Data).
	Example: If 32 threads are computing lighting for 32 pixels, they form a warp.
	Divergence: If some threads take different branches, execution slows (they serialize).

live example: rendering a 3D rotating cube with a shiny texture on the screen
Scene Setup: A cube with 8 vertices. Light source above it. Camera in front. Each face textured with a logo. We want to render a single frame of this cube.

Graphics Rendering - Pipeline Stages: The graphics pipeline takes 3D scene description (geometry, materials, lights, camera) and turns it into a 2D image.

Vertices of the cube are stored in vertex buffers:
	V1 = (-1, -1, -1), V2 = (1, -1, -1), ...
	Each vertex also has UV coords (for textures) and normals (for lighting).

	1. Vertex Processing:
		Input: Vertex buffers (position, normals, texture coordinates).
		Vertex Shader: Programmable stage, transforms 3D vertices → clip space using matrices (model, view, projection). Can compute per-vertex lighting, skinning (for animation), etc.
		Runs per vertex. Applies transformation:
			screen_pos = ProjectionMatrix * ViewMatrix * ModelMatrix * vertex
			Example: V1 = (-1, -1, -1) → after transformations → (200, 300) in screen space.
	Outputs: new position, interpolated UV, normal.
	2. Tessellation: Breaking big polygons into finer triangles for detail. Used for smooth surfaces (car models, terrains) without storing huge meshes. Hardware Tessellation pipeline (3 parts):
			Tessellation Control Shader (decides how much to subdivide).
			Fixed-function Tessellator (splits polygons into smaller pieces).
			Tessellation Evaluation Shader (computes positions of new vertices).
		Suppose one cube face is a single quad (2 triangles). Tessellation subdivides it into smaller triangles → smoother shading if camera is close. And smoothes cube edges.
			Example: One face subdivided into 16 triangles.
	3. Geometry Shading: Works on whole primitives (triangle, line, point). Can create or discard geometry.
		Example: particle systems (emit more points), shadow volume extrusion, silhouette edges.
		Works on primitives (triangles).
		Example: If cube is far away, geometry shader might discard tiny triangles (optimization). Or could add extra geometry like outlining cube edges (for a wireframe effect).
	4. Clipping & Projection: Triangles outside the camera view (frustum) are discarded. Remaining are mapped into screen space (2D coordinates).
		Example: If 3 cube faces are behind the camera, they get clipped away.
	5. Binning / Tiling: Screen is divided into tiles/bins (like 16×16 pixel blocks). Triangles are sorted into bins where they might appear.
		Advantage: Reduces memory bandwidth, improves cache locality.
		Tile-based GPUs (like ARM Mali, Qualcomm Adreno, Apple GPUs) rely heavily on binning.
			Screen = 800×600 pixels, divided into 16×16 tiles.
			Each triangle is mapped to tiles it overlaps.
				Example: One cube face overlaps 200 tiles → recorded in bin list.
	6. Rasterization/Fragmentation: Converts vector primitives (triangles) → fragments (potential pixels). Each fragment stores interpolated data from vertices (color, UV, normal).
		Example: A triangle covering 200 pixels → 200 fragments generated.
		Converts each triangle → fragments (potential pixels).
			Example: A triangle covers 250 pixels → 250 fragments generated.
				Each fragment stores:
				Interpolated UV
				Interpolated normal
				Depth value
	7. Shading: Fragment Shader / Pixel Shader runs per-fragment. Computes the final color using:
		Textures (images mapped to surfaces)
		Lighting models (Phong, PBR, etc.)
		Material properties (metallic, roughness, etc.)
		Runs per fragment (per-pixel shading).
			Example:
				Reads texture at UV = (0.3, 0.5).
				Computes lighting using Phong model:
				color = texture * (ambient + diffuse + specular)
				For a shiny pixel → output might be (0.8, 0.7, 0.9).
	8. Merging / Blending: Fragments are combined with existing framebuffer values. Examples:
		Transparency (alpha blending).
		Depth test (closer pixels overwrite farther ones).
		MSAA (multi-sample anti-aliasing merges multiple samples into one pixel).
			Depth Test: If fragment is behind an existing pixel, discard it.
			Blending: If cube face is transparent, mix old color + new color:
				final_color = src * alpha + dst * (1 - alpha)
			Example: If fragment color = (0.8, 0.7, 0.9, alpha=0.5)
				Background = (0.0, 0.0, 0.0)
				→ Output = (0.4, 0.35, 0.45)

Advanced Concepts:
	Ray Tracing: Instead of rasterizing, simulate rays of light bouncing in the scene.Rays are traced through BVH (bounding volume hierarchy) acceleration structures. Produces more realistic reflections, refractions, shadows, and GI (global illumination).Usually hybrid: rasterization for base image, ray tracing for lighting details.
		For realistic reflections (cube reflects light source).
	Foveated Rendering: Based on human vision (sharp in fovea, blurry in periphery). Eye-tracking detects where user is looking → render full resolution only there, lower resolution elsewhere. Saves performance in VR/AR.
		In VR headset, only cube’s center is rendered in full res.
	Compute Shaders: General-purpose parallel programs running on GPU (outside graphics pipeline). Used for physics, AI, image processing, GPU-based ML.

Other Important Stages
	Culling: Remove triangles facing away (backface culling).
	LOD (Level of Detail): Swap models/textures depending on distance.
	Deferred Shading: Store geometry info (G-buffer), compute lighting in later pass (better for many lights).
	Post-Processing: Bloom, depth of field, motion blur, tone mapping.
	VRS (Variable Rate Shading): Shade blocks of pixels together (saves power, like coarse shading).
		Far away corners shaded at lower rate.
	MRT (Multiple Render Targets): One pass outputs multiple buffers (for G-buffer, shadow maps).
	After final image, bloom effect makes highlights glow.
	Textures & UV Maps:
		UV maps → 2D coordinates mapping texture image onto cube.
		Normal maps → fake small bumps for detailed lighting.
			Example: Cube face logo is a PNG, normal map adds “engraved” feel.
	Buffers:
		ARGB buffer: stores color (Alpha, Red, Green, Blue).
		Z-buffer (Depth buffer): tracks depth of each pixel → nearer pixels overwrite farther ones.
			Example: Cube front pixel at depth=0.3 overwrites background pixel at depth=0.8.
	Anti-aliasing (SSAA/MSAA):
		Super-sampling (SSAA): render cube at 4× resolution, downsample.
		MSAA: multiple samples per pixel edge only.
			Example: Cube edges look smooth instead of jagged.
	Alpha Blending: For transparent objects.
		Formula: final = src*alpha + dst*(1-alpha)
			Example: Glass cube face at alpha=0.5 blends with background.
	Shadows & Reflections:
		Shadow maps: Render scene from light’s POV → mark cube’s pixels in shadow.
		Reflections: Cube surface uses reflection vector to fetch environment texture.
	Billboards:
		2D sprites always facing camera.
			Example: A fire particle near cube rendered as billboard quad, not real 3D.
	Render to Texture:
		Instead of sending final image to screen, render cube to a texture.
			Example: Cube reflection on floor = scene rendered into texture, then mapped on plane.
	Deferred Rendering:
		First pass: output cube’s G-buffer (position, normal, albedo).
		Second pass: compute lighting for all pixels.
			Example: Adding 10 lights to cube costs little extra.
	Advanced Shading:
		Specular shading: highlights where cube reflects light directly.
		PBR (physically based rendering): realistic metal/roughness values.
	Ray Tracing + CNN:
		RT cores trace rays from cube’s shiny surface → BVH acceleration structure → find lamp reflection. Result = noisy image. Tensor cores run CNN (deep learning) to denoise reflection.
			Example: Cube now shows clean, accurate reflection of lamp.
	Deep Learning Super Sampling (DLSS): Game renders cube at 1080p.
		Tensor cores upscale + sharpen → output looks like 4K. AI model trained offline to reconstruct high-res details.
	Final Blending + Post-Processing:
		ROP units merge fragments into framebuffer.
		Bloom effect → cube highlights glow.
		Motion blur if cube spins fast.

Master Mental Map
	Vertices → [Vertex Shader] 
			  → [Tessellation] 
			  → [Geometry Shader] 
			  → [Clipping / Projection] 
			  → [Binning / Tiling] 
			  → [Rasterization] 
			  → [Fragment Shader / Shading] 
			  → [Merging / Blending] 
			  → Final Image
	(Parallel to this: Ray Tracing, Compute Shaders, Foveation, Post-Processing)

Warp Example: When shading the cube’s pixels, suppose 32 fragments fall into one warp. GPU executes lighting shader instruction once, all 32 fragments compute in parallel. If half fragments need reflection and half don’t → warp divergence (serialized execution).

Final Image: Cube with 6 textured faces, shiny highlights, depth-correct blending, all tiles merged → full rendered frame.

Display refresh faster than human eye perception → cube appears smoothly rotating.

Graphics pipeline = Vertices → (vertex shader, tessellation, geometry) → rasterization → (fragment shader) → blending → buffers → final image.

Compute vs Rendering: Are they different?
	Rendering pipeline: Purpose: Convert 3D scene → 2D image.
		Stages: Vertex shader → tessellation → geometry shader → rasterization → fragment shader → blending.
		Fixed-function + programmable stages. Runs in a very structured order, optimized for triangles, pixels, and images.
	Compute pipeline: Purpose: Run general parallel workloads on the GPU (not just graphics).
		Stages: Only compute shader kernels, no fixed order.
		Examples: physics simulation, AI inference, matrix multiplication, image filtering. Programmer controls grid/blocks/threads (e.g. CUDA, OpenCL).

	Both share the same GPU HW execution units (ALUs, SIMD lanes).
		Example: In NVIDIA, both rasterization shaders and CUDA kernels run on the SMs (Streaming Multiprocessors).

	Difference is how the front-end schedules work:
		Graphics pipeline = “assembly line” specialized for triangles → pixels.
		Compute = “free-form” jobs running directly on shader cores.

	We can even mix them: e.g., render base image with rasterization, then run compute shaders for post-processing bloom.

-------------

GPU hardware building blocks:
	CUDA Cores (aka FP/INT ALUs):
		The “basic execution units” in NVIDIA GPUs (other vendors have different names: AMD → Stream Processors, Intel → EUs). They are SIMD lanes that execute the instructions for warps (32 threads).
		They work on:
			Vertex shading, fragment shading, geometry shading.
			General compute (CUDA kernels, OpenCL, Vulkan compute).
			Physics, AI, image processing if coded as normal math ops.
			Example (our cube):
				Computing per-fragment lighting:
				color = texture * (ambient + diffuse + specular)
			Think of CUDA cores as the “CPUs” of the GPU, but massively parallel and vectorized.
	Tensor Cores
		Specialized matrix-multiply units, introduced by NVIDIA in Volta/Turing. Optimized for deep learning operations (matrix × matrix → accumulate).
		They work on:
			Neural network inference/training.
			DLSS (Deep Learning Super Sampling) in gaming: upscale low-res cube → high-res cube image.
			AI denoising for ray tracing.
		Example (our cube): Ray tracing produces a noisy reflection. Tensor cores run a trained AI model to clean the reflection → smooth shiny cube.
		Think of having turbo-charged math coprocessors for matrix-heavy math.
	Ray Tracing (RT) Cores
		Hardware units specialized for ray traversal and BVH (Bounding Volume Hierarchy) intersection tests. Normally very expensive if done on CUDA cores.
		They work on: Shooting rays for shadows, reflections, global illumination. Accelerating ray-triangle intersection.
		Example (our cube):
			You look at a shiny cube. RT cores compute whether a reflection ray from pixel (200, 300) hits another object (like a lamp).
		Think like having a “physics coprocessor” inside the GPU just for ray-object collision.
	Texture Units (TMUs): Handle texture sampling & filtering.
		Example: Cube’s face gets color from a PNG logo at UV (0.3, 0.5).
	ROP Units (Render Output Units): Handle raster ops: depth test, blending, MSAA.
		Example: Cube’s transparent face merges with background.
	Geometry/Tessellation Units: Handle fixed-function tessellation.
		Example: Subdividing cube’s face into smaller triangles.
	Rasterizers: Convert triangles → fragments.
		Example: Front face of cube covering 200 pixels → 200 fragments.
	SM (Streaming Multiprocessor): A block that contains many CUDA cores + schedulers + registers.
		Example: One SM may hold 128 CUDA cores, 4 Tensor cores, 1 RT core.

CUDA cores (shader cores): general math, shading, transformations.
Shading cores = basically CUDA cores running graphics shaders.
Tensor cores: accelerate ML (matrix multiplies) → DLSS, denoising.
RT cores: accelerate ray tracing intersections.

Usual HW: Mostly CUDA cores + helper units (RT, Tensor, TMUs, ROPs).
